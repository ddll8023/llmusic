# 歌词管理模块开发设计

> 本文档针对 LLMusic 中的歌词管理模块，描述该模块的需求、项目内结构与流程、数据库和 API 设计。代码组织见 `doc/项目结构文档.md`，业务定位见 `doc/模块说明文档.md`。

---

## 1. 需求

### 模块目标

歌词管理模块负责歌词的获取、解析与同步展示，解决"用户如何在听歌时看到同步滚动的歌词"这一需求。它支持多来源、多格式歌词，并提供沉浸式全屏歌词页与桌面歌词悬浮窗。

### 功能需求

- 本地歌曲歌词按来源优先级获取：内嵌标签歌词 → 同目录歌词文件 → 纯文本兜底
- 解析标准 LRC（时间戳）、带时间轴 JSON（syncText）、纯文本三种格式；同时间戳多行自动合并为翻译/罗马音；支持逐字歌词时间轴
- 播放进度驱动歌词行高亮与自动滚动，用户可手动调整同步偏移量、开关翻译/罗马音显示
- 在线歌曲经后端元数据包获取歌词（LRC 文本）并解析展示
- 沉浸式歌词页：全屏滚动展示、动态背景光晕、封面取色驱动氛围色、装饰动画（声波/粒子等）
- 桌面歌词悬浮展示：独立透明置顶窗口显示当前句/翻译/罗马音与逐字高亮，支持拖拽、锁定穿透、字号、单/双行、当前行/下一行颜色与置顶（默认开启）
- 动画自适应：性能模式关闭装饰动画、页面隐藏暂停动画、系统减弱动态效果偏好自动降级
- 存量数据修复：数据库歌词丢失时间戳时，播放时自动从音频文件重新提取带时间戳歌词

### 非功能需求

- 歌词解析结果按歌曲 LRU 缓存（上限 200 条），标签写回可能改写歌词时联动失效
- 歌词加载失败不阻塞播放（静默降级为空态）
- 逐字歌词需要 100ms 级进度上报支撑
- 歌词缓存失效必须与标签写回联动，避免展示过期歌词

### 当前范围与明确不做项

- 歌词存储优先保留原始文本格式，不主动改写数据库歌词
- 不实现歌词搜索与编辑（预留扩展点）
- 任务栏歌词、壁纸歌词等桌面歌词扩展形态暂不实现

### 与其他模块的职责边界

- 被音乐播放模块依赖（进度驱动索引推进、播放时加载歌词）
- 依赖标签与封面模块的缓存失效通知（标签写回后歌词缓存失效）
- 本地歌词数据源（songs.lyrics 字段）由音乐扫描模块写入、标签与封面模块联动更新
- 桌面歌词依赖主进程 NowPlaying 快照/广播，由播放 store 推送播放状态与歌词数据

### 验收标准

- 三种来源、三种格式的歌词均正确解析展示
- 逐字歌词按字高亮；翻译/罗马音开关生效；偏移量调整即时生效
- 标签写回后再次播放展示新歌词（缓存未失效不展示旧值）
- 性能模式下歌词页无装饰动画
- 桌面歌词窗口显示当前句/逐字/翻译，切歌、暂停、seek 后同步正确；锁定穿透、拖拽、字号/单双行/颜色设置与重启恢复正常

## 2. 该项目的模块结构与流程

### 项目级模块关系

```
音乐播放 ──进度/歌曲──> 歌词管理 <──缓存失效── 标签与封面
音乐扫描 ──歌词入库──>    │
在线搜索/歌单 ──元数据包──> │
                       └──展示──> 歌词页（窗口与 UI 壳）
                       └──展示──> 桌面歌词窗口（主进程 NowPlaying 广播）
```

### 当前代码边界

- 渲染层状态：歌词 store（行列表、当前索引、偏移量、翻译/罗马音开关、来源/格式元信息）、桌面歌词 store（启用/锁定/字号/单双行/颜色）
- 渲染层展示：歌词页组件（滚动、动画、背景取色）、播放控制栏歌词入口、桌面歌词独立窗口组件
- 渲染层同步：播放 store 向主进程推送 NowPlaying 快照与位置锚点
- 主进程 IPC 层：歌词处理器（按歌曲获取歌词，带 LRU 缓存与文件重提取兜底）、桌面歌词处理器（窗口/配置/快照/位置）
- 主进程窗口层：桌面歌词窗口管理（透明置顶、锁定穿透、拖拽、配置持久化）
- 主进程解析层：LRC/JSON/纯文本解析、逐字解析、时间戳工具
- 共享提取模块：歌词文本提取（ID3v2 USLT、VorbisComment、syncText 重建、同目录 .lrc）

### 核心业务流程

1. 播放本地歌曲 → 播放 store 委托歌词 store 加载 → IPC 获取歌词 → 主进程按"内嵌 → 外部 .lrc"解析
2. 内嵌纯文本且无时间戳 → 尝试从文件重新提取 LRC（修复存量数据）；仍失败按纯文本展示
3. 播放进度上报 → 按时间戳推进当前行索引（正常播放 O(1) 游标，seek 后重扫）→ 高亮与滚动
4. 在线播放 → 按 songMid 拉取下载元数据包中的歌词文本 → 前端解析 LRC 展示（异步，不阻塞播放）
5. 桌面歌词 → 播放 store 推送完整快照（歌曲/歌词/偏移/翻译开关）与 5Hz 位置锚点 → 主进程广播 → 桌面歌词窗口 RAF 插值渲染
6. 标签写回 → 标签处理器通知歌词缓存失效 → 下次播放重新解析

### 数据流和状态流

- 创建：songs.lyrics / 外部 .lrc / 在线文本 → 解析 → LyricLine[]（time/text/timeText/translation/roma/words）
- 缓存：解析成功结果按 songId 入 LRU；失效由标签写回触发
- 状态：currentIndex（-1 表示无当前行）、syncOffset、showTranslation/showRoma、isAutoScrolling
- 桌面歌词同步：主进程维护 NowPlayingSnapshot（track/lyric/position/playing/speed/lyricOffsetMs），向桌面歌词窗口广播

### 异常、并发与任务规则

- 在线歌词加载为 fire-and-forget，按 songMid 校验防切歌串词
- 播放进度推进使用游标优化，seek 场景从头重扫
- 解析失败降级：LRC 无有效行视为无歌词，不抛错

### 关键技术选择

- 解析统一在主进程完成并缓存，渲染层只消费结构化结果
- 逐字歌词以"行内 <时间戳>字"扩展语法承载，解析为 words 数组
- 桌面歌词采用独立 Vue 多页入口 + 透明置顶 BrowserWindow；位置同步用低频锚点 + RAF 插值，避免高频 IPC

## 3. 数据库的设计

本模块不新增表，使用 songs 表的歌词相关字段：

- `lyrics`（TEXT）：入库时提取的歌词原始文本（来源为音乐扫描模块）
- `hasLyrics`（INTEGER）：是否有歌词标记，查询前置过滤

### 数据语义

- 数据库歌词为原始文本快照，本模块读取后解析，不写回数据库
- 歌词内容可能含用户歌词文件内容，属于用户本地数据，不进日志
- 缓存（LRU，200 条）仅存解析结果于主进程内存，随应用退出释放
- 数据生命周期：歌词字段随歌曲记录生命周期；标签写回后重新解析同步更新 songs 表（由标签与封面模块执行）

### 结构变更策略

无表结构变更；若未来支持歌词搜索需评估 lyrics 字段的索引与更新策略（设计假设：当前无此需求）。

## 4. API 接口的设计

本模块的公开边界为 Electron IPC 与渲染层内部的跨 store 调用。

### IPC 接口

| 通道 | 调用方向 | 入参 | 返回要点 |
|---|---|---|---|
| get-lyrics | 渲染 → 主进程 | songId | `{ lyrics: LyricLine[], format, source, metadata }`；无歌词返回失败 |
| validate-tag-changes / update-song-tags（联动） | 渲染 → 主进程 | — | 标签写回成功后主进程内部触发歌词缓存失效 |
| now-playing-update | 主渲染 → 主进程 | track/lyric/position/playing/speed/lyricOffsetMs/showTranslation/showRoma | 更新 NowPlaying 快照并广播给桌面歌词窗口 |
| now-playing-position | 主渲染 → 主进程 | position/playing/speed | 更新位置锚点并广播给桌面歌词窗口 |
| desktop-lyric-request-snapshot | 桌面歌词窗口 → 主进程 | 无 | 返回当前 NowPlaying 快照 |
| desktop-lyric-get-state | 渲染 → 主进程 | 无 | 返回当前桌面歌词配置 |
| desktop-lyric-set-enabled / desktop-lyric-update-config / desktop-lyric-close | 主渲染/桌面窗口 → 主进程 | 启用状态/配置片段/无 | 创建/销毁窗口、持久化配置、广播配置变化 |
| desktop-lyric-cursor-inside | 主进程 → 桌面歌词窗口 | 光标是否在窗口内 | 用于锁定态 hover 显示控制栏 |
| desktop-lyric-set-unlock-button-bounds | 桌面歌词窗口 → 主进程 | 解锁按钮命中区域 | 锁定态下仅该区域可点击 |
| desktop-lyric-move / desktop-lyric-save-state | 桌面歌词窗口 → 主进程 | x/y 或空 | 移动窗口、保存位置/尺寸 |

### 跨 store 调用边界

- 播放 store → 歌词 store：`loadLyrics(songId)`（本地）、`loadOnlineLyricsByMid(songMid)`（在线）
- 播放 store → 歌词 store：`setCurrentIndex`（进度推进）、`displayLines`（读取）
- 歌词页 → 播放 store：`seekToLyricPosition`（点击歌词行跳转播放进度）
- 播放 store → 主进程：`syncNowPlayingToMain` / `syncNowPlayingPosition`（桌面歌词数据源）
- 桌面歌词窗口 → 主进程：拉取快照、订阅快照/位置事件、上报解锁按钮区域

### 错误边界

- 歌词获取失败返回统一 `{ success: false, error }`，前端重置为空态，不弹错误提示（非关键路径）
- 在线歌词加载失败静默，不阻塞播放
- 缓存失效为内部函数调用，不暴露为独立 IPC

### 前端调用关系

- 歌词页组件消费歌词 store 的展示派生数据（displayLines、currentLine）
- 自动滚动与高亮由组件基于 currentIndex 实现，store 只维护索引状态
- 桌面歌词窗口独立消费主进程广播的 NowPlaying 快照与位置锚点，不直接访问主应用 Pinia
