# QQ 音乐歌单模块开发设计

> 本文档针对 LLMusic 中的 QQ 音乐歌单模块，描述该模块的需求、项目内结构与流程、数据库和 API 设计。代码组织见 `doc/项目结构文档.md`，业务定位见 `doc/模块说明文档.md`。

---

## 1. 需求

### 模块目标

QQ 音乐歌单模块把用户 QQ 音乐账号下的歌单资源带入桌面端，解决"用户如何在桌面端延续在线听歌习惯"这一需求。它提供账号歌单与"我喜欢"列表的浏览、整单播放与下载。

### 功能需求

- 登录后侧边栏展示账号创建的歌单列表与"我喜欢"列表；未登录时提示登录
- 用户进入歌单详情页后可加载歌单全部歌曲（自动迭代所有页码），支持按歌曲名/歌手筛选
- 支持整单播放（随机模式下随机起点）、单曲点击即播并进入歌词页
- 支持歌单内单曲下载与批量勾选下载（含失败重试）
- 支持歌单刷新（清除缓存重新拉取）与加载失败重试

### 非功能需求

- 歌单歌曲缓存于前端进程内（按歌单 ID 键控），重复进入不重复拉取
- 切换歌单时清理筛选词与选中集，防止旧歌单数据串场
- 全量加载歌单必须保证分页迭代完整，不丢曲
- 未登录状态清空全部在线歌单缓存

### 当前范围与明确不做项

- 只读浏览账号在线歌单，不提供在线歌单的编辑（创建/改名/增删曲）能力
- 与本地播放列表相互隔离，无数据互通
- 歌单内歌曲播放前需先获取试听地址（远程数据）

### 与其他模块的职责边界

- 依赖 QQ 音乐登录（凭证与登录状态联动）
- 复用音乐播放（整单/单曲播放）、音乐下载（单曲/批量下载）、统一歌曲表格（在线模式展示）

### 验收标准

- 登录后歌单列表可见，进入任一歌单能完整加载全部歌曲
- 整单播放按当前播放模式生效，随机模式起点随机
- 批量下载失败项可一键重试
- 登出后歌单数据清空，重新登录自动恢复

### 范围外事项

- 在线歌单编辑（增删歌曲、排序、改名）当前未实现，如需支持需新增后端写接口并评估 SDK 能力
- 歌单封面本地缓存策略当前未设计（每次展示使用远程 URL，设计假设：封面加载由前端图片缓存承担）

## 2. 该项目的模块结构与流程

### 项目级模块关系

```
QQ 音乐登录 ──登录态/凭证──> QQ 音乐歌单 ──播放──> 音乐播放
                                  │ ──下载──> 音乐下载
                                  └──展示──> 统一歌曲表格（窗口与 UI 壳）
```

### 当前代码边界

- 后端 API 层：用户歌单列表、喜欢歌曲、歌单歌曲（单页/全部）四个路由
- 后端服务层：用户歌单与喜欢列表获取、歌单详情（单页/自动迭代全部）、批量回填播放 URL
- 渲染层：歌单 store（用户歌单列表、详情缓存、下载编排、刷新/清理）、歌单详情页组件（筛选、播放、下载交互）

### 核心业务流程

1. 登录成功 → 前端自动加载用户歌单列表，识别"我喜欢的音乐"歌单 ID
2. 进入歌单详情 → 命中缓存直接展示；未命中拉取全部歌曲（"我喜欢"走喜欢列表接口，其余走全部接口），批量获取播放 URL 回填
3. 整单播放 → 组装播放队列（含 URL）交给播放 store，随机模式生成随机起点
4. 批量下载 → 勾选歌曲 → 共享下载编排（选目录、分块并发、失败重试）
5. 刷新歌单 → 清除该歌单缓存重新拉取
6. 登出 → 清空歌单列表与全部缓存，停止相关播放

### 数据流和状态流

- 创建：歌单 ID → 全部歌曲 → 播放 URL 回填 → 前端缓存
- 失效：刷新清除单歌单缓存；登出清空全部
- 状态：加载中/刷新中/错误态，当前歌单与缓存条目一致

### 异常与竞态规则

- 播放 URL 批量获取失败不阻塞歌单展示，播放时跳过无地址条目
- 切换歌单（setCurrentPlaylistId）先清空当前歌曲与错误，防止旧数据串场
- 全量加载使用分页迭代器并带页数上限保护

### 关键技术选择

- 歌单详情全部加载由后端一次性迭代返回，前端无需处理分页循环
- "我喜欢"列表与普通歌单走不同后端接口，前端按歌单 ID 判断路由

## 3. 数据库的设计

本模块不直接持久化数据：歌单与歌曲均为 QQ 音乐账号的远程数据。

- 前端缓存：按歌单 ID 键控的进程内 Map（歌曲列表 + 总数），登录态下存活
- 数据时效：播放 URL 带时效性，不落盘、不跨会话恢复（登出即清）
- 数据删除责任：登出时由登录模块联动清理本模块缓存；本地音乐库不受影响

## 4. API 接口的设计

本模块接口为 HTTP，挂载在统一 QQ 音乐路由前缀 `/api/v1/qqmusic` 下。遵循项目后端规范：全部路由使用 POST，请求体使用 Pydantic Request Schema，响应统一为 `{code, message, data}`。

### 接口列表

| 路径 | 方法 | 请求 Schema | 响应 data 要点 | 说明 |
|---|---|---|---|---|
| /user/playlists | POST | 无 | 歌单列表（ID、标题、封面、歌曲数、创建时间）+ total | 需登录 |
| /user/liked | POST | page、pageSize | 喜欢歌曲列表 + total | 需登录，按 encrypt_uin 查询 |
| /playlist/{playlist_id}/songs | POST | page、pageSize、requestId | 歌单单页歌曲 + total | 单页获取 |
| /playlist/{playlist_id}/songs/all | POST | requestId | 歌单全部歌曲（自动迭代）+ total | 附带批量播放 URL 回填 |

### 鉴权与错误边界

- 未登录/凭证过期返回对应错误码（2001/2002），前端联动登录状态
- 服务层统一捕获 SDK 异常（登录过期/未登录/限流）映射错误码，日志记录不泄露细节
- 单曲详情失败不影响批量结果（降级空链接）

### 幂等与分页语义

- 查询接口幂等；全部歌曲接口内部迭代上限 50 页防失控
- 播放 URL 批量获取与歌曲列表解耦，失败可重试

### 前端调用关系

- 统一经前端 API 入口调用；登录成功/登出由登录模块触发本模块加载/清空
- 歌单详情页复用统一歌曲表格在线模式与共享下载编排
- 播放队列组装在播放 store 完成，本模块只提供数据与入口
