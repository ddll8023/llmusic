# 操作日志模块开发设计

> 本文档针对 LLMusic 中的操作日志模块，描述该模块的需求、项目内结构与流程、数据和 API 设计。代码组织见 `doc/项目结构文档.md`，业务定位见 `doc/模块说明文档.md`。

---

## 1. 需求

### 模块目标

操作日志模块用于记录应用运行过程中的重要网络请求和关键业务操作，为后期错误排查提供可检索的本地日志。日志只面向开发者，不直接展示在普通页面上；用户需在设置中开启“开发者模式”后，才会出现日志页面入口。

### 功能需求

- 记录重要网络请求：记录 QQ 音乐业务接口的请求路径、HTTP 状态、耗时、错误码等概要信息。
- 记录重要操作：记录登录成功/失败、退出登录、凭证自动刷新成功/失败等关键认证事件。
- 日志持久化到后端目录：写入 `backend/logs/operation.log`，采用 JSON Lines 格式，每行一条结构化日志。
- 提供日志查询接口：支持分页、级别筛选、日志类型筛选和关键词搜索。
- 提供日志清理接口：按保留天数删除过期日志，支持 7～30 天范围。
- 提供日志展示页面：页面展示时间、级别、类型、动作、内容、状态、耗时等信息，并提供清理过期日志入口。
- 开发者模式开关：设置页提供“开发者模式”开关；开启后侧边栏显示“开发者日志”入口，关闭后入口隐藏。

### 非功能需求

- 日志写入必须轻量，不能阻塞业务主流程；写入失败不能影响正常业务。
- 日志文件不进入版本库，需加入 `.gitignore`。
- 日志中不得包含密码、Token、Cookie、密钥、二维码内容等敏感数据。
- 日志查询接口仅服务于本地开发者页面，不引入额外鉴权；开发者模式仅是前端入口控制，不是安全边界。
- 日志文件采用追加写入，读取时按行解析；单行损坏不影响其他行。
- 日志清理按记录时间判断，使用临时文件写入并原子替换，清理失败时保留原文件。
- 页面刷新/分页时避免记录日志查询请求本身，防止日志页自增长。

### 当前范围与明确不做项

- 不记录完整请求/响应 Body，只记录请求行、状态、耗时和错误码概要。
- 不实现日志文件自动轮转、压缩或导出；日志清理采用按记录时间保留 7～30 天的策略。
- 不实现服务端权限校验；开发者模式属于前端展示控制。
- 不记录 Electron 主进程日志，当前只覆盖后端 HTTP 与认证操作。

### 与其他模块的职责边界

- 被登录认证模块调用：记录登录、登出、凭证刷新事件。
- 被 HTTP 中间件调用：记录 QQ 音乐业务请求。
- 被前端日志页面调用：通过查询和清理 API 读取、清理日志。
- 与现有 `backend/app/utils/logger.py` 运行日志互补：运行日志输出到控制台，操作日志落盘供开发者页面查看。

### 验收标准

- 开启开发者模式后，侧边栏出现“开发者日志”入口，点击可进入日志页面。
- 日志页面能分页展示已记录的请求和操作，支持级别/类型/关键词筛选。
- 执行一次 QQ 音乐搜索或登录操作后，日志文件中能查到对应记录。
- 关闭开发者模式后，侧边栏入口消失，但已记录日志不删除。
- 手动清理 7 天或 30 天以前的日志后，保留期限内的记录仍可查询。
- 后端启动后自动清理过期日志，清理失败不影响业务接口。

## 2. 该项目的模块结构与流程

### 项目级模块关系

```
HTTP 请求 → FastAPI 中间件 → 操作日志服务 → backend/logs/operation.log
认证服务 → 操作日志服务 → backend/logs/operation.log
前端日志页面 → 操作日志查询 API → 操作日志服务 → backend/logs/operation.log
```

### 当前代码边界

- 后端 API 层：维护 `backend/app/api/operation_log.py`，提供日志查询和清理接口，挂在 `/api/v1/operation-log` 前缀下。
- 后端服务层：维护 `backend/app/services/operation_log.py`，负责日志写入、读取、分页、筛选和按时间清理。
- 后端模型层：维护 `backend/app/schemas/operation_log.py`，定义查询、清理请求与日志响应模型。
- 后端基础设施：在 `backend/app/main.py` 中注册中间件和路由，并启动操作日志自动清理任务；中间件调用日志服务记录业务请求。
- 前端页面层：维护 `sys_vue/src/components/pages/OperationLog.vue`，展示、筛选和清理过期日志。
- 前端状态层：维护 `sys_vue/src/store/operationLog.ts`，管理日志分页、筛选、清理和加载状态。
- 前端设置层：在 `sys_vue/src/store/ui.ts` 增加开发者模式状态，在 `Settings.vue` 增加开关。
- 前端导航层：在 `SideBar.vue` 根据开发者模式显示“开发者日志”入口，在 `App.vue` 注册页面。

### 核心业务流程

1. 业务请求进入后端：中间件记录开始时间 → 调用业务接口 → 响应返回后写入一条 `request` 类型日志（路径、状态、耗时）。
2. 认证操作发生：登录成功、登出、凭证刷新成功/失败时，认证服务调用日志服务写入一条 `auth` 类型日志。
3. 开发者查看日志：前端日志页面调用查询 API → 日志服务读取 JSON Lines 文件 → 按分页/筛选条件返回 → 页面展示。
4. 清理日志：应用启动后及每日定时调用清理服务；开发者也可在日志页面选择保留天数并确认清理。

### 数据流和状态流

- 写入：调用方传入结构化字段 → 日志服务组装 JSON 行 → 追加写入 `backend/logs/operation.log`。
- 读取：查询 API 传入分页/筛选参数 → 日志服务逐行解析文件 → 倒序分页返回最新日志。
- 清理：以日志 `time` 字段计算截止时间 → 将保留行写入同目录临时文件 → `os.replace` 原子替换原文件。
- 文件状态：首次写入时自动创建 `backend/logs` 目录和文件；文件不存在时查询和清理均返回空结果。

### 异常、并发与事务规则

- 日志写入、查询快照和清理使用同一个进程内 `asyncio.Lock` 串行化，避免清理覆盖并发写入。
- 同步文件操作通过线程执行，避免阻塞 FastAPI 事件循环。
- 日志写入失败只记录运行日志 warning，不向业务调用方抛异常。
- 日志文件单行 JSON 或时间解析失败时保留该行并计数，不影响其他日志清理。
- 清理通过同目录临时文件和原子替换完成；替换失败时保留原文件。

### 关键技术选择

- 使用 JSON Lines 文件而非数据库：日志为追加型数据，文件方式实现简单、可直接用文本工具查看，符合“保存到后端目录”的需求。
- 使用 FastAPI 中间件统一记录请求，避免在每个业务函数手动埋点。
- 使用独立日志服务封装读写，业务模块只调用 `log_operation`，不直接操作文件。

## 3. 数据库的设计

本模块不直接使用 SQLite 数据库，持久化数据为后端目录下的 JSON Lines 日志文件。

### 日志文件

- 路径：`backend/logs/operation.log`
- 格式：每行一个 JSON 对象，UTF-8 编码，`ensure_ascii=False`。
- 写入方式：追加写，使用 `asyncio.Lock` 保证并发安全。
- 目录创建：首次写入时通过 `os.makedirs(exist_ok=True)` 自动创建。
- 文件忽略：`backend/logs/` 加入 `.gitignore`，不进入版本库。

### 日志行结构

| 字段 | 类型 | 说明 |
|---|---|---|
| time | str | ISO 8601 本地时间 |
| level | str | INFO / WARNING / ERROR |
| type | str | 日志类型：request / auth |
| action | str | 动作描述，如请求路径或操作名称 |
| message | str | 人类可读说明 |
| status | int | HTTP 状态码（request 类型） |
| duration_ms | int | 请求耗时毫秒（request 类型） |
| error_code | int | 业务错误码，0 表示成功 |
| detail | object | 可选补充信息，禁止包含敏感字段 |

### 数据生命周期与隐私

- 默认保留最近 30 天日志，可通过 `APP_OPERATION_LOG_RETENTION_DAYS` 配置为 7～30 天。
- 应用启动后立即执行一次自动清理，之后每 24 小时执行一次。
- 前端手动清理支持 7～30 天范围；当前页面预设 7 天和 30 天，不提供全部清空。
- 日志中不得写入 Token、Cookie、密钥、二维码内容等敏感数据。
- 查询接口只返回日志行内容，不返回文件路径等内部信息。

## 4. API 接口的设计

本模块提供 HTTP 接口，挂载在 `/api/v1/operation-log` 前缀下。遵循项目后端规范：所有接口统一使用 POST，请求体使用 Pydantic Request Schema，响应统一为 `{code, message, data}`。

### 接口列表

| 路径 | 方法 | 请求 Schema | 响应 data | 说明 |
|---|---|---|---|---|
| /api/v1/operation-log/list | POST | `OperationLogListRequest` | `PaginatedResponse[OperationLogItem]` | 分页查询操作日志 |
| /api/v1/operation-log/cleanup | POST | `OperationLogCleanupRequest` | `OperationLogCleanupResult` | 清理保留期限以前的操作日志 |

### 查询日志

请求体：

```json
{
  "page": 1,
  "page_size": 20,
  "level": "WARNING",
  "log_type": "auth",
  "keyword": "登录"
}
```

字段说明：

- `page`：页码，从 1 开始，默认 1。
- `page_size`：每页数量，默认 20，最大 100。
- `level`：可选，按级别筛选，`INFO` / `WARNING` / `ERROR`。
- `log_type`：可选，按类型筛选，`request` / `auth`。
- `keyword`：可选，模糊匹配 action、message、detail 中的文本。

响应 data：

```json
{
  "lists": [
    {
      "time": "2026-08-15T10:00:00+08:00",
      "level": "INFO",
      "type": "request",
      "action": "POST /api/v1/qqmusic/song/search",
      "message": "请求完成",
      "status": 200,
      "duration_ms": 32,
      "error_code": 0,
      "detail": {}
    }
  ],
  "pagination": {
    "page": 1,
    "page_size": 20,
    "total": 1,
    "total_pages": 1
  }
}
```

### 清理日志

请求体：

```json
{
  "retention_days": 30
}
```

- `retention_days`：保留天数，范围为 7～30 天，页面预设 7 天和 30 天。
- 清理条件为日志时间早于当前时间减去保留天数。
- JSON 损坏或时间无法解析的日志行保留不删除。
- 响应返回保留天数、截止时间、删除条数、保留条数和异常行条数。
- 清理失败返回统一错误响应；自动清理失败只记录运行日志。

响应 data：

```json
{
  "retention_days": 30,
  "cutoff_time": "2026-07-16T10:00:00+08:00",
  "deleted_count": 128,
  "retained_count": 642,
  "invalid_count": 0
}
```

### 错误边界

- 参数校验失败由全局 `RequestValidationError` 处理器返回 `PARAM_ERROR`。
- 查询时文件不存在或读取失败返回空列表；清理时文件不存在视为无操作，其他清理失败返回统一内部错误。
- 本模块接口不要求登录鉴权；开发者模式仅控制前端入口。

### 前端调用关系

- 前端通过 `sys_vue/src/api/operationLog.ts` 发起请求，客户端基地址为 `/api/v1/operation-log`，相对调用路径为 `/list` 和 `/cleanup`，对应完整接口路径为 `/api/v1/operation-log/list` 和 `/api/v1/operation-log/cleanup`。
- 日志页面 Store 管理分页、筛选和清理状态，页面组件负责展示、确认和交互。
- 日志查询请求不会被中间件记录，避免日志页自增长。

### 鉴权与权限边界

- 当前为本地单机应用，日志接口不额外鉴权。
- 开发者模式开关只控制 UI 入口，不承担安全授权职责；若后续需要保护日志内容，应增加服务端权限校验。
