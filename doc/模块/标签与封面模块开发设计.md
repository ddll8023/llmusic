# 标签与封面模块开发设计

> 本文档针对 LLMusic 中的标签与封面模块，描述该模块的需求、项目内结构与流程、数据库和 API 设计。代码组织见 `doc/项目结构文档.md`，业务定位见 `doc/模块说明文档.md`。

---

## 1. 需求

### 模块目标

标签与封面模块负责歌曲元数据的查看与编辑，解决"用户如何修正和美化歌曲信息"这一需求。它支持标签读取/写入、封面提取，并保证写回后数据库与相关缓存一致。

### 功能需求

- 用户可查看歌曲文件的标签（标题、歌手、专辑、年份、时长、码率、采样率、格式、编码）
- 用户可编辑标签并写回音频文件：MP3/FLAC 等经转码工具以流拷贝方式写元数据；写入前做数据校验（标题非空、年份范围、字段长度）
- 用户可对未入库的文件直接读取/写入标签（经文件路径接口）
- 用户可提取歌曲封面：内嵌封面优先，其次同目录封面文件（歌名/cover/folder/专辑名命名），并可按需强制重新提取
- 封面读取带字节上限的 LRU 缓存，含"确认无封面"负缓存，避免无封面歌曲反复整文件解析
- 标签写回可能改写歌词时联动失效歌词缓存，并重新解析文件同步数据库记录

### 非功能需求

- 写回过程必须安全：先写临时文件，备份原文件，失败恢复备份
- 所有文件路径入参必须经统一安全校验（绝对路径 + 扩展名白名单）
- 标签数据校验在写回前完成，校验错误返回明细
- 写回成功后数据库记录同步更新；同步失败给出明确警告

### 当前范围与明确不做项

- 只处理单文件元数据，不做批量改写（批量界面归元数据管理页，能力复用本模块）
- 封面替换（写入新封面到文件）当前未实现，仅提取与展示
- 不负责标签的在线搜索匹配（在线元数据搜索在主进程歌曲处理器中，属在线能力）

### 与其他模块的职责边界

- 被音乐扫描（入库时封面/歌词提取，本模块提供共享提取能力）、音乐播放（封面展示）、本地音乐库（记录同步）依赖
- 依赖本地音乐库（歌曲记录读取/更新）、歌词管理（缓存失效联动）
- 元数据管理页（窗口与 UI 壳内页面）聚合本模块能力提供批量编辑交互

### 验收标准

- 标签编辑写回文件成功，重新读取为最新值；数据库记录同步更新
- 写回失败（如文件只读）时原文件完整无损
- 无封面歌曲第二次请求不重复整文件解析（负缓存命中）
- 非法路径请求被拒绝

### 范围外事项

- 封面替换写入当前未实现（需评估各格式封面写入链路，设计建议：后续复用下载模块的标签写入能力）
- 批量标签编辑的并发写回策略当前未设计（现为逐文件顺序处理）

## 2. 该项目的模块结构与流程

### 项目级模块关系

```
元数据管理页 / 音乐库页 ──> 标签与封面 <──歌词缓存失效── 歌词管理
        │                        │
        └──歌曲记录读/写──> 本地音乐库（songs 表）
```

### 当前代码边界

- 主进程 IPC 层：标签处理器（按歌曲 ID 或文件路径读写标签、校验）、封面处理器（按歌曲 ID 或路径提取封面）
- 主进程能力层：标签校验（标题/年份/长度规则）、写回执行（ffmpeg 流拷贝 + 备份恢复）、封面解析（内嵌 + 目录探测）、封面 LRU 缓存（按字节淘汰 + 负缓存）
- 数据访问层：歌曲仓库（记录读取、写回后重新解析并更新）
- 渲染层：元数据管理页与音乐库页的标签编辑器、封面展示组件

### 核心业务流程

1. 读取标签：按歌曲 ID 查记录取路径 → 解析文件（跳过封面）→ 返回标签与格式
2. 编辑写回：校验标签 → 校验路径/扩展名 → ffmpeg 流拷贝到临时文件 → 备份原文件 → 替换 → 成功删除备份/失败恢复备份
3. 写回后同步：失效歌词缓存 → 重新解析文件生成新记录 → 更新数据库 → 前端定点替换歌曲记录
4. 提取封面：查缓存（含负缓存）→ 未命中解析内嵌封面 → 未命中探测同目录封面文件 → 缓存结果（含无封面负缓存）
5. 强制提取：删除该歌曲缓存项后重新提取
6. 文件级操作（未入库文件）：路径校验后直接读写标签/封面，不涉及数据库

### 数据流和状态流

- 创建：文件标签 → 校验 → 临时文件 → 目标文件（备份保障）
- 流转：写回 → 重新解析 → 数据库更新 → 前端替换 → 缓存失效
- 缓存：封面按 (songId 或 file:path) 键控，字节超限淘汰最旧；删除歌曲时清缓存项
- 删除：无封面负缓存随普通条目同生命周期；清空歌曲时整体清空

### 异常、并发与安全规则

- 写回失败路径：替换失败先尝试恢复备份，恢复失败记录错误
- 所有文件操作前校验：isAudioPath（绝对路径 + 白名单扩展名）
- 解析/写回异常统一捕获转 `{ success: false, error }`，不泄露堆栈
- 数据库同步失败不否定写回成功（返回警告），用户可重新扫描修复

### 关键技术选择

- 写回使用 ffmpeg 流拷贝（-c copy）避免重编码损坏音质
- 封面缓存按累计字节数（50MB）而非条数淘汰，适配大封面场景

## 3. 数据库的设计

本模块不新增表，使用 songs 表记录并在写回后更新：

- 读取：按 songId 查询 filePath、libraryId 等
- 更新：写回成功后重新解析文件，按 id 整体更新歌曲记录（复用歌曲仓库 updateSong）
- 字段变化：title/artist/album/year 等随写回结果变化；hasLyrics/lyrics 随重新解析同步
- 封面不持久化在数据库（songs.cover 仅扫描期标记），实际封面内容存于缓存与文件内嵌

### 缓存生命周期

- 封面 LRU（主进程内存）：歌曲删除/清空时同步清除对应缓存项
- 负缓存语义：null 值条目成本记账（64 字节），避免无封面歌曲反复解析
- 歌词缓存失效由标签写回触发（跨模块联动）

### 结构变更策略

无表结构变更；字段随歌曲仓库统一维护。

## 4. API 接口的设计

本模块的公开边界为 Electron IPC（渲染进程 → 主进程）。

### 标签相关 IPC

| 通道 | 调用方向 | 入参 | 返回要点 |
|---|---|---|---|
| get-song-tags | 渲染 → 主进程 | songId | `{ tags, format, song }` |
| update-song-tags | 渲染 → 主进程 | `{ songId, tags }` | `{ updatedSong, validation, warning? }`；成功后同步失效歌词缓存 |
| validate-tag-changes | 渲染 → 主进程 | tags | `{ validation: { valid, errors, warnings } }` |
| get-tags-from-file | 渲染 → 主进程 | filePath | `{ tags, format }`；路径校验 |
| update-tags-to-file | 渲染 → 主进程 | `{ filePath, tags }` | `{ updatedTags }`；路径校验，不触数据库 |

### 封面相关 IPC

| 通道 | 调用方向 | 入参 | 返回要点 |
|---|---|---|---|
| get-song-cover | 渲染 → 主进程 | songId | `{ cover(base64), format, source }`；含缓存 |
| force-extract-cover | 渲染 → 主进程 | songId | 同上；先清缓存项强制重提 |
| get-cover-from-file | 渲染 → 主进程 | filePath | 同上；路径校验，不依赖数据库 |

### 错误边界

- 校验失败返回错误明细数组（标题/年份/长度），前端就地展示
- 写回失败返回错误并保证原文件完整（备份恢复语义）
- 歌曲不存在、路径非法、格式不支持（扩展名不在白名单）显式返回错误
- 无封面返回 `{ success: false, error: "未找到封面" }`，前端展示默认图

### 前端调用关系

- 元数据管理页与音乐库页经统一 IPC 调用；标签编辑器组件封装交互
- 写回成功后前端用返回的 updatedSong 定点替换列表记录（不整表重载）
- 封面展示组件按歌曲 ID 请求并处理负缓存结果（无封面即默认图）
