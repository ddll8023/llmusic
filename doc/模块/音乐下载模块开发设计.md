# 音乐下载模块开发设计

> 本文档针对 LLMusic 中的音乐下载模块，描述该模块的需求、项目内结构与流程、数据库和 API 设计。代码组织见 `doc/项目结构文档.md`，业务定位见 `doc/模块说明文档.md`。

---

## 1. 需求

### 模块目标

音乐下载模块把在线音频保存到用户本地磁盘并自动写入元数据，解决"如何把在线音乐变成本地收藏"这一需求。它覆盖单曲下载与批量下载，并负责文件名安全、并发限流、失败重试与元数据嵌入。

### 功能需求

- 用户可下载单曲（弹出保存对话框指定位置）或批量下载（选择目标目录）
- 批量下载展示逐曲进度（排队/下载中/成功/失败），完成后可一键重试失败项
- 下载文件自动写入元数据：MP3 写 ID3v2 标签（标题、歌手、专辑、音轨、流派、年份、歌词、封面），FLAC 写 Vorbis 注释与封面
- 下载完成前临时文件随机命名，完成后原子落盘；目标目录文件名冲突自动追加序号
- 元数据写入失败时降级保留纯音频文件并向用户提示警告
- 文件名防路径逃逸校验，目标目录必须为绝对路径

### 非功能需求

- 主进程侧独立并发限流（上限 3）与失败自动重试（2 次），不依赖渲染层约束
- 流式写盘避免大文件驻留内存；封面获取失败不阻塞音频保存
- 下载地址与元数据由后端一次性聚合返回（详情、封面、歌词、链接并行组装）
- 单曲下载地址缺失时前端直接跳过，不发起无效请求

### 当前范围与明确不做项

- 不负责下载地址与元数据的获取（由在线音乐搜索、QQ 音乐歌单模块提供）
- 下载只落盘到用户指定位置，不自动写入本地音乐库（用户经导入能力入库）
- 不实现断点续传与下载任务持久化（当前为会话内一次性任务）

### 与其他模块的职责边界

- 依赖在线音乐搜索、QQ 音乐歌单（下载源与元数据包）
- 下载产物经本地音乐库的文件导入能力入库；歌词数据写入文件供歌词管理模块读取

### 验收标准

- 单曲/批量下载成功，MP3 与 FLAC 标签与封面正确写入
- 批量下载并发不超过 3，失败项重试可用
- 非法文件名或目标路径被拒绝，不产生越界文件
- 元数据写入失败时仍保留可播放的音频文件

### 范围外事项

- 断点续传、下载队列持久化、下载历史记录当前未实现，属后续能力
- 非 mp3/flac 格式的标签写入当前不执行（仅保存音频），扩展格式需同步补充标签写入链路

## 2. 该项目的模块结构与流程

### 项目级模块关系

```
在线音乐搜索 / QQ 音乐歌单 ──歌曲+元数据包──> 音乐下载 ──文件──> 本地磁盘
                                                      │
                                                      └──(经导入)──> 本地音乐库
```

### 当前代码边界

- 渲染层：共享下载编排（composable，单曲/批量/重试，进度状态），供发现页与歌单 store 复用
- 渲染层 API：下载元数据包获取（后端聚合接口）
- 主进程 IPC 层：单曲下载（保存对话框）、批量下载（目录 + 文件名防逃逸 + 冲突序号）
- 主进程下载执行：并发信号量、重试、流式写盘、ID3/Vorbis 标签写入、临时文件清理

### 核心业务流程

1. 单曲下载：前端组装元数据（文件名 = 歌名 - 歌手）→ 弹保存对话框 → 主进程下载
2. 批量下载：前端选择目录 → 按并发 3 分块执行 → 每曲独立状态上报
3. 主进程下载：网络请求（重试 2 次）→ 流式写临时音频 → 获取封面 → 写标签（MP3/FLAC）→ 产出临时成品 → 拷贝到目标路径 → 清理临时文件
4. 失败重试：前端记录失败项与目标目录，重试时仅重新执行失败曲目

### 数据流和状态流

- 创建：下载元数据包（详情/歌词/封面/链接）→ 临时文件（音频/封面/成品）→ 目标文件
- 流转：进度状态 per 曲目（pending/downloading/success/failed）
- 删除：临时文件无论成败统一清理；目标文件不自动删除
- 前端状态：downloadingIds（单曲去重）、batchProgress（批量总览）

### 异常、并发与重试规则

- 并发上限在下载入口处通过信号量统一控制（主进程侧，不信任渲染层限流）
- 网络请求失败自动重试 2 次；标签写入失败降级保留纯音频 + warning
- 单曲下载中途取消（保存对话框取消）返回 canceled，不计为失败

### 关键技术选择

- 元数据包由后端一次聚合（三路并行），减少前端多次往返
- MP3 用标签库直写、FLAC 用 ffmpeg 写 Vorbis 注释，按扩展名分流
- 临时文件使用随机 UUID 命名，避免并发下载相互覆盖

## 3. 数据库的设计

本模块不直接持久化数据：下载任务、进度与元数据均为会话内数据，落盘产物为音频文件。

- 进度与重试上下文仅存在于前端 composable 内存（lastBatchSongs、lastTargetDir），会话结束即失效
- 下载产物生命周期由用户管理：应用不跟踪、不自动删除已下载文件
- 元数据（标签/歌词/封面）写入音频文件本身，供标签与封面、歌词管理模块读取
- 隐私边界：下载文件包含用户选择的歌曲内容，路径不进入日志

## 4. API 接口的设计

本模块不提供 HTTP 接口，公开边界为 Electron IPC（渲染进程 → 主进程）。

### IPC 接口

| 通道 | 调用方向 | 入参 | 返回要点 |
|---|---|---|---|
| download-song-with-metadata | 渲染 → 主进程 | url、filename、metadata（标题/歌手/专辑/音轨/流派/年份/歌词/封面 URL/格式） | `{ filePath, warning? }`；取消返回 canceled |
| download-song-to-dir | 渲染 → 主进程 | 上述 + targetDir | `{ filePath, warning? }`；文件名须通过安全校验 |

### 元数据包获取（HTTP，依赖在线模块）

| 路径 | 方法 | 说明 |
|---|---|---|
| /song/download-bundle | POST | 返回详情、专辑、歌词、下载链接聚合包；失败时前端降级使用搜索结果中的基础信息 |

### 错误边界

- 入参校验：filename 不得含路径分隔符与 ".."，targetDir 必须绝对路径，否则返回非法路径错误
- 网络失败重试耗尽后返回"音频下载失败"；标签失败返回成功 + warning（降级语义）
- 下载中并发由主进程信号量排队，不拒绝请求

### 前端调用关系

- 前端统一经 `window.electronAPI` 调用，经共享下载编排封装
- 发现页与歌单页复用同一编排，不各自实现下载逻辑
- 下载完成不触发自动入库（事实），如需入库由用户走文件导入
