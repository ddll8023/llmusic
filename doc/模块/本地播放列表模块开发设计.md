# 本地播放列表模块开发设计

> 本文档针对 LLMusic 中的本地播放列表模块，描述该模块的需求、项目内结构与流程、数据库和 API 设计。代码组织见 `doc/项目结构文档.md`，业务定位见 `doc/模块说明文档.md`。

---

## 1. 需求

### 模块目标

本地播放列表模块是歌曲的主题组织工具，解决"用户如何按自己的主题组织本地歌曲"这一需求。它支持歌单的创建、编辑、删除与歌曲分配，并可整单播放。

### 功能需求

- 用户可创建歌单（名称、描述），编辑与删除已有歌单
- 用户可向歌单添加歌曲、从歌单移除歌曲，歌单内顺序按添加次序维护
- 用户可浏览歌单详情（歌单内歌曲列表）与歌单列表
- 用户可整单播放歌单（交由音乐播放模块执行）
- 删除歌曲时自动从所有歌单中移除引用（由本地音乐库模块联动）

### 非功能需求

- 歌单歌曲加载优先复用内存缓存（媒体库已加载歌曲），未命中部分并行查询
- 歌单数据变更后刷新内存状态，避免脏读
- 歌单操作参数校验（空 ID、空歌曲列表拒绝）
- 歌曲顺序由关联表 position 维护，调整操作保持顺序一致

### 当前范围与明确不做项

- 只管理本地歌单，与 QQ 音乐在线歌单相互隔离
- 不实现歌单排序拖拽（position 已支持，交互未实现）
- 不实现歌单封面自定义（coverImgId 字段保留未用）

### 与其他模块的职责边界

- 依赖本地音乐库（歌曲数据与删除联动）
- 被音乐播放模块消费（整单播放入口）
- 歌单删除/歌曲移除由本模块数据层执行，前端 store 同步状态

### 验收标准

- 歌单 CRUD 全程数据一致，删除歌单不影响歌曲记录
- 向歌单添加不存在的歌曲 ID 被忽略；重复添加不产生重复项
- 删除歌曲后所有歌单自动移除该引用
- 整单播放从歌单首曲开始

### 范围外事项

- 歌单内拖拽排序当前未实现；position 已就绪，交互层补全即可（设计建议：后续按需实现）
- 歌单封面（coverImgId）字段已预留但无 UI 与写入路径

## 2. 该项目的模块结构与流程

### 项目级模块关系

```
本地音乐库 ──歌曲数据──> 本地播放列表 ──整单播放──> 音乐播放
      ^                        │
      └──删除歌曲联动清理引用───┘
```

### 当前代码边界

- 渲染层状态：歌单 store（列表、当前歌单、歌曲加载缓存优先、对话框状态）
- 主进程 IPC 层：歌单处理器（CRUD、增删歌曲）
- 数据访问层：歌单仓库（playlists / playlist_songs 关联管理，position 排序组装）
- 数据库：与歌曲库同一 SQLite 连接

### 核心业务流程

1. 加载歌单列表 → 读取 playlists 全表 → 每个歌单按 position 组装 songId 数组
2. 进入歌单详情 → 优先从媒体库内存缓存取歌曲对象，未命中走 IPC 并行查询
3. 添加歌曲 → 校验歌单存在、歌曲存在、未重复 → 取最大 position + 1 追加 → 更新歌单时间戳
4. 移除歌曲 → 按 (playlistId, songId) 删除关联 → 更新歌单时间戳
5. 删除歌单 → 事务内先删关联再删歌单
6. 整单播放 → 取歌单歌曲 ID 列表 → 播放 store 组装队列从首曲播放
7. 歌曲删除联动 → 歌曲仓库删除歌曲时清其全部歌单引用并刷新受影响歌单时间戳

### 数据流和状态流

- 创建：playlists 行 + playlist_songs 行（事务）
- 流转：position 单调递增维护顺序；歌单更新时间戳随增删刷新
- 删除：歌单删除级联清关联；歌曲删除清引用（由歌曲仓库事务完成）
- 前端状态：playlists 数组、currentPlaylistSongs、对话框编辑态

### 异常、并发与事务规则

- 歌单创建（含初始歌曲）、删除、歌曲增删各自为事务
- 添加/移除歌曲按 ID 校验存在性，忽略无效项不中断
- 前端加载失败保留旧数据并给出错误信息

### 关键技术选择

- 关联表 position 显式建模顺序，避免依赖插入顺序
- 歌曲对象组装优先复用媒体库内存，减少 IPC 往返

## 3. 数据库的设计

数据库：SQLite（`llmusic.db`），WAL 模式，连接与建表 DDL 集中在数据库连接层。本模块读写 `playlists` 与 `playlist_songs` 两张表。

### playlists 表（歌单）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | TEXT | PRIMARY KEY | UUID |
| name | TEXT | NOT NULL | 歌单名称 |
| description | TEXT | NOT NULL DEFAULT '' | 描述 |
| coverImgId | TEXT | 可空 | 封面标识（当前未使用） |
| createTime / updateTime | INTEGER | NOT NULL | 创建/更新时间（毫秒） |

### playlist_songs 表（歌单-歌曲关联）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| playlistId | TEXT | PRIMARY KEY (复合) | 歌单 ID |
| songId | TEXT | PRIMARY KEY (复合) | 歌曲 ID |
| position | INTEGER | NOT NULL | 歌单内序号，排序依据 |

### 索引与查询

- 复合主键 (playlistId, songId) 保证歌单内歌曲唯一
- 按歌单查询关联时使用 playlistId 前缀索引 + position 排序
- 歌曲侧查询（某歌曲在哪些歌单）使用 songId 前缀（复合主键第二列，删除歌曲联动用）

### 实体关系与生命周期

- 歌单 1:N 歌曲（关联表）；未声明物理外键，由业务代码保证一致性（歌曲删除时清引用）
- 删除歌单：事务内清关联 + 删歌单
- 删除歌曲：歌曲仓库事务内清该歌曲全部关联并刷新歌单时间戳

### 事务与一致性

- 所有写操作均为单事务；position 计算在事务内执行避免并发重复
- 前端缓存一致性：写操作后按当前视图决定重载详情或列表

### 结构变更策略

按项目规范（无迁移）：修改建表 DDL 后删除 `llmusic.db` 重建（需授权）。

## 4. API 接口的设计

本模块不提供 HTTP 接口，公开边界为 Electron IPC（渲染进程 → 主进程）。

### IPC 接口

| 通道 | 调用方向 | 入参 | 返回要点 |
|---|---|---|---|
| get-playlists | 渲染 → 主进程 | 无 | `{ playlists }`（含 songs 数组） |
| get-playlist-by-id | 渲染 → 主进程 | playlistId | `{ playlist }` |
| create-playlist | 渲染 → 主进程 | `{ name?, description?, coverImgId?, songs? }` | `{ playlist }` |
| update-playlist | 渲染 → 主进程 | playlistId、`{ name?, description?, coverImgId? }` | `{ playlist }` |
| delete-playlist | 渲染 → 主进程 | playlistId | 删除歌单与关联 |
| add-songs-to-playlist | 渲染 → 主进程 | playlistId、songIds | `{ addedCount }` |
| remove-songs-from-playlist | 渲染 → 主进程 | playlistId、songIds | `{ removedCount }` |

### 错误边界

- 歌单不存在、参数无效返回 `{ success: false, error }`
- 添加时歌曲不存在/已存在被忽略（addedCount 反映实际新增数），不视为错误
- 数据层异常统一捕获转错误信息，不抛出未处理异常

### 前端调用关系

- 歌单 store 统一调用 IPC 并维护本地状态；页面组件只做交互
- 添加/移除成功后按当前视图重载（当前歌单详情或歌单列表）
- 整单播放经播放 store 的 playSongFromList 组装队列
