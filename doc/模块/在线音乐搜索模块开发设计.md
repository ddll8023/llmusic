# 在线音乐搜索模块开发设计

> 本文档针对 LLMusic 中的在线音乐搜索模块，描述该模块的需求、项目内结构与流程、数据库和 API 设计。代码组织见 `doc/项目结构文档.md`，业务定位见 `doc/模块说明文档.md`。

---

## 1. 需求

### 模块目标

在线音乐搜索模块是连接 QQ 音乐曲库的发现入口，解决"用户如何找到想听的在线歌曲"这一需求。它提供关键词搜索与分享链接解析两种方式，产出可试听、可下载的歌曲结果。

### 功能需求

- 用户输入关键词分页搜索歌曲，可切换页码与每页条数
- 用户可粘贴 QQ 音乐歌曲或歌单分享链接，自动识别目标类型并加载
- 搜索结果先展示基础信息，封面与试听地址异步补全，不阻塞页面渲染
- 翻页结果缓存，回看已翻页面直接命中缓存并补全封面/地址
- 搜索结果可发起单曲试听（交给音乐播放模块）与单曲/批量下载（交给音乐下载模块）
- 登录状态影响试听质量：有凭证优先 FLAC，无凭证降级低码率试听；未登录时给出引导

### 非功能需求

- 搜索请求带 requestId 标识，页面切换时旧响应不得覆盖新结果
- 分页缓存按搜索条件键控，新搜索清空缓存
- 封面/地址补全失败不阻塞主流程，失败静默降级
- 接口超时合理（下载类大超时，搜索类短超时）

### 当前范围与明确不做项

- 不触发下载动作（下载由音乐下载模块执行）
- 不管理登录凭证（归 QQ 音乐登录模块）
- 仅支持 QQ 音乐平台；新增平台遵循平台注册配置，不另起请求通道

### 与其他模块的职责边界

- 依赖 QQ 音乐登录（凭证决定试听质量与可用性）
- 被音乐下载（下载地址与元数据）、音乐播放（在线试听）消费

### 验收标准

- 关键词搜索分页正确，翻页回看秒开
- 分享链接（歌曲/歌单）解析成功并加载对应结果
- 未登录时搜索可用、试听降级、并有登录引导

### 范围外事项

- 在线歌单的完整浏览（列表、详情、整单播放）由 QQ 音乐歌单模块负责
- 试听质量策略（FLAC 优先、ACC_96 降级）当前固定在后端服务层，暂不提供用户可配置项（设计假设：当前产品阶段无此需求）

## 2. 该项目的模块结构与流程

### 项目级模块关系

```
QQ 音乐登录 ──凭证──> 在线音乐搜索 ──试听──> 音乐播放
                          │ ──下载──> 音乐下载
```

### 当前代码边界

- 后端 API 层：搜索、专辑封面、歌曲链接、下载元数据包、关键词搜索五个路由（统一 QQ 音乐路由前缀）
- 后端服务层：分享链接解析（302 重定向提取 songid/id）、歌曲详情/歌单详情、关键词搜索、封面 URL 模板、歌曲链接（FLAC 降级 ACC_96）
- 后端数据模型层：歌曲/歌单/专辑/链接等 Pydantic 响应模型
- 渲染层：发现页 store（搜索模式、分页、缓存、异步补全、下载编排）、统一 API 入口（axios 封装）

### 核心业务流程

1. 关键词搜索：前端调用关键词接口 → 后端调 SDK 搜索 → 组装歌曲列表 → 前端分页缓存并展示骨架 → 异步补全封面与试听地址
2. 分享链接搜索：前端提交 urlType + searchUrl → 后端解析重定向得到资源 ID → 按类型取歌曲详情或歌单单页 → 返回结果
3. 封面补全：批量取专辑 MID → 后端按模板生成封面 URL 列表
4. 试听地址补全：批量取歌曲 MID → 后端有凭证取 FLAC，失败或未登录降级 ACC_96 → 前端回填 songUrl
5. 播放/下载：结果条目携 songUrl 交给播放或下载模块

### 数据流和状态流

- 创建：关键词/链接 → 搜索结果 → 前端缓存（按条件键控）
- 流转：封面/URL 异步回填更新缓存条目并标记补全状态
- 失效：新搜索清空缓存；登出时发现页数据由登录模块联动清理
- 前端状态：searchMode、page/pageSize、loading、searchStep（searching/covers/urls/done）

### 异常与重试规则

- 后端统一捕获 SDK 异常并映射业务错误码（登录过期/未登录/限流/服务错误），前端按错误码分流
- 封面与 URL 补全失败静默，条目保留基础信息
- 分页请求以当前请求 ID 判定，旧响应丢弃

### 关键技术选择

- 后端负责分享链接解析与 SDK 调用，前端不直接访问第三方接口
- 搜索结果补全采用"先骨架后补全"两段式，兼顾响应速度与信息完整

## 3. 数据库的设计

本模块不直接持久化数据：搜索结果全部为远程数据，仅存在于前端进程内缓存。

- 前端搜索缓存（Map，键 = 搜索条件 + 页码）：条目含歌曲列表、总数、封面/URL 补全标记；新搜索清空，登出联动清理
- 歌曲试听地址由后端实时生成，带凭证时效性，不落盘
- 数据删除责任：前端缓存生命周期随搜索会话；登出时由登录模块清理在线相关状态

## 4. API 接口的设计

本模块接口为 HTTP，挂载在统一 QQ 音乐路由前缀 `/api/v1/qqmusic` 下。遵循项目后端规范：全部路由使用 POST，请求体使用 Pydantic Request Schema，响应统一为 `{code, message, data}`（经统一 success/error 构造器），SDK 异常在服务层统一映射错误码。

### 接口列表

| 路径 | 方法 | 请求 Schema | 响应 data 要点 | 说明 |
|---|---|---|---|---|
| /song/search | POST | urlType（song/playlist）、searchUrl、page、pageSize、requestId | 歌曲列表或歌单歌曲列表 + total | 分享链接解析后取详情（双返回类型） |
| /song/search-by-keyword | POST | keyword、page、pageSize、requestId | 歌曲列表 + total | 关键词搜索 |
| /song/album-img | POST | albumIdList（≤200）、requestId | 封面 URL 列表 | 按专辑 MID 模板生成 |
| /song/song-url | POST | songIdList（≤200）、requestId | 歌曲 URL 列表（url + urlType） | 有凭证 FLAC，无凭证/失败降级 ACC_96 |
| /song/download-bundle | POST | songMid、requestId | 下载元数据包（详情、专辑、歌词、下载链接） | 三段并行聚合，供下载模块使用 |

### 鉴权与错误边界

- 凭证经服务层凭证访问器读取，不要求前端传凭证；未登录时自动降级匿名试听
- 错误码：未登录（2001）、凭证过期（2002）、限流（4002）、参数错误（1001）、服务错误（4001）
- 分享链接解析失败（非 302、缺参数）按参数错误返回

### 幂等、分页与缓存语义

- 搜索接口幂等；分页由 page/pageSize 承载，前端按键控缓存
- 歌单详情分页与"全部歌曲"（自动迭代页码，上限 50 页）两个接口分离，供不同场景使用
- requestId 用于前后端请求关联，不参与业务幂等

### 前端调用关系

- 统一经前端 API 入口调用；响应拦截器解包信封并联动登录状态
- 发现页 store 负责分页缓存与异步补全；播放/下载复用共享下载编排
- 新增平台时在平台注册配置中登记导航项，接口层沿用统一入口
