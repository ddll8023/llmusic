# 全局通知与错误反馈模块开发设计

> 本文档针对 LLMusic 中的全局通知与错误反馈模块，描述该模块的需求、项目内结构与流程、数据库和 API 设计。代码组织见 `doc/项目结构文档.md`，业务定位见 `doc/模块说明文档.md`。

---

## 1. 需求

### 模块目标

全局通知与错误反馈模块是统一的用户反馈体系，解决"用户如何及时、可理解地获知操作结果"这一需求。它取代原生弹窗，覆盖成功、错误、警告、信息四类场景，并对错误做统一分类提示。

### 功能需求

- 全局 Toast 提示：右上角堆叠展示，自动消失，点击可关闭
- 四种类型：成功/错误/警告/信息，样式区分
- 短时间同文案去重（2.5 秒窗口），避免重复操作刷屏
- 统一错误分类提示：业务错误（携带错误码）展示业务文案；网络错误提示"网络连接失败"；其余系统错误提示"系统异常"
- 登录状态联动：识别未登录/凭证过期错误码时自动复位前端登录状态（引导重新扫码）
- 主进程侧降级警告（如下载元数据写入失败）经返回结构透传为通知

### 非功能需求

- 通知展示时长可配（默认 3 秒），队列无上限但同文案去重
- 通知文案面向用户可理解，不暴露内部异常细节与堆栈
- 去重记录定期清理，避免 Map 无限增长

### 当前范围与明确不做项

- 只负责反馈呈现，不处理业务逻辑
- 不做通知中心（历史记录、已读管理）
- 不做桌面系统通知（Electron Notification 未启用，事实）

### 与其他模块的职责边界

- 被所有模块依赖（统一反馈出口）；业务模块只调用通知入口，不自行弹窗
- 登录状态联动仅修改认证 store 状态，业务清理由登录模块完成

### 验收标准

- 各类操作（成功/失败/警告）均有对应通知
- 连续相同操作只弹一次提示
- 后端未启动时请求网络错误提示文案正确
- 凭证过期错误触发登录状态复位与提示

## 2. 该项目的模块结构与流程

### 项目级模块关系

```
全部业务模块 ──成功/错误/警告/信息──> 全局通知 <──错误码── 前端 API 入口
                                           │
                                           └──登录状态联动──> 登录模块
```

### 当前代码边界

- 渲染层状态：通知 store（toast 队列、同文案去重记录、分类提示入口）
- 渲染层展示：Toast 容器组件（右上角堆叠、过渡动画、点击关闭）
- 错误分类能力：依赖前端 API 入口的 ApiError（携带业务错误码）与 axios 网络错误识别

### 核心业务流程

1. 业务模块调用成功/错误/警告/信息入口 → 同文案去重检查 → 入队并启动自动消失计时
2. 异常路径：任意模块捕获异常后调用统一错误分类入口 → 按类型（业务/网络/系统）映射文案 → 入队
3. 凭证联动：API 响应拦截器识别未登录/凭证过期错误码 → 更新登录 store 状态（isLoggedIn=false、isExpired 标记）→ 后续操作自然引导重新登录
4. 用户点击 Toast → 从队列移除；自动超时移除

### 数据流和状态流

- 创建：消息 → 去重检查 → 队列 push（id/type/message）
- 删除：点击/超时移除；去重记录按窗口期清理
- 状态：toasts 数组驱动容器渲染，纯前端内存态，无持久化

### 异常与并发规则

- 通知调用本身不抛错（message 空则忽略）
- 网络错误识别覆盖 axios 错误码（ERR_NETWORK/ECONNABORTED/ETIMEDOUT）与文案兜底
- 凭证联动经动态导入登录 store，避免循环依赖

### 关键技术选择

- 单一 store + 容器组件的发布订阅模式，模块间解耦
- 错误分类以错误类型判断优先级：业务错误 > 网络错误 > 系统错误

## 3. 数据库的设计

本模块不直接持久化数据：

- 通知队列与去重记录均为渲染进程内存态，应用退出即清
- 无历史记录、无用户数据、无隐私责任
- 依赖的登录状态由登录模块管理，本模块只读触发

## 4. API 接口的设计

本模块不提供对外 API（无 HTTP、无 IPC 通道），公开边界为渲染层内部的 store 调用接口：

### 内部调用边界

| 入口 | 调用方 | 说明 |
|---|---|---|
| notify(type, message, duration?) | 全部业务模块 | 通用通知 |
| success / error / info / warning | 全部业务模块 | 类型化快捷入口 |
| notifyError(e) | 各模块异常处理路径 | 统一错误分类：ApiError → 业务文案；网络错误 → 网络失败提示；其余 → 系统异常提示 |
| remove(id) | Toast 容器 | 手动关闭 |

### 错误边界

- 未知错误必须走 notifyError 分类，不允许直接向用户展示原始异常信息
- 取消类结果（用户取消对话框、取消扫描）不弹错误提示
- 凭证联动为旁路行为：API 层完成状态复位，本模块不重复提示

### 调用约定

- 页面与 store 统一经通知 store 发消息，禁止组件内自建提示
- 新增业务错误码时同步接入错误分类映射与登录状态联动
