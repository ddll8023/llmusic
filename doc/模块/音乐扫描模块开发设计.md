# 音乐扫描模块开发设计

> 本文档针对 LLMusic 中的音乐扫描模块，描述该模块的需求、项目内结构与流程、数据库和 API 设计。代码组织见 `doc/项目结构文档.md`，业务定位见 `doc/模块说明文档.md`。

---

## 1. 需求

### 模块目标

音乐扫描模块将用户本地磁盘目录中的音频文件批量解析并写入歌曲库，解决"如何把分散在磁盘上的音乐批量纳管"这一需求。它是本地音乐库的数据来源，提供全量重扫与增量扫描两种模式，并在后台线程执行以免阻塞界面。

### 功能需求

- 用户对某个音乐库发起扫描后，递归遍历目录下全部受支持格式的音频文件
- 全量重扫先清空该库歌曲记录再扫描；增量扫描跳过 mtime 未变化的文件并统计跳过数
- 解析并入库歌曲元数据：标题、艺术家、专辑、时长、码率、采样率、格式、年份、流派、音轨号、碟片号、文件大小
- 提取歌词（内嵌标签 → 同目录歌词文件 → 纯文本）与封面存在性标记
- 扫描过程实时上报阶段与进度（找文件、解析元数据、保存入库）
- 用户可取消扫描；取消后已解析部分仍入库
- 单个文件解析失败不中断扫描，失败清单（路径 + 原因）随完成事件上报

### 非功能需求

- 扫描在 Worker 线程执行，主进程只做编排与入库，不阻塞 UI 与 IPC
- 解析按批次并行（每批 20 个文件），进度按批上报
- 扫描有超时保护（1 小时）与代次校验：延迟回调必须校验代次，防止误伤新扫描
- 扫描进行中禁止删除/清空/导入歌曲，避免与入库竞争

### 当前范围与明确不做项

- 只读文件元数据，不修改源文件内容
- 不管理音乐库 CRUD（归本地音乐库模块）；本模块只消费库目录路径
- 不负责封面内容提取（封面按需由标签与封面模块提取），扫描只记录有无封面标记

### 与其他模块的职责边界

- 依赖本地音乐库模块的库查询与歌曲批量写入能力（songRepo 仓库）
- 为本地音乐库模块提供入库数据；扫描完成事件由前端媒体库 store 消费并刷新列表

### 验收标准

- 对含多层子目录的目录扫描，全部音频文件正确入库，进度实时可见
- 增量扫描仅解析变更文件，跳过数统计正确
- 取消扫描后界面进入空闲态，已入库歌曲保留
- 损坏文件在失败清单中体现，不影响其他文件入库

## 2. 该项目的模块结构与流程

### 项目级模块关系

```
用户（前端媒体库）──发起/取消──> 音乐扫描 ──写入──> 歌曲库（songs 表）
       ^                                │
       └──── 进度/完成/失败清单事件 ─────┘
```

### 当前代码边界

- 渲染层：媒体库 store 的扫描 action（进度事件监听只注册一次、扫描完成后强制重载歌曲并刷新库列表）
- 主进程 IPC 层：扫描处理器（开始/取消，进度节流推送，扫描状态互斥）
- 主进程编排层：扫描器（worker 生命周期、代次管理、超时、取消与终止）
- Worker 线程：文件遍历、按批并行解析、歌词提取、失败收集、进度上报
- 数据层：歌曲批量写入（事务 upsert，复用歌曲仓库）

### 核心业务流程

1. 前端发起扫描（libraryId + 是否清空重扫）
2. 主进程校验库存在、路径可访问，取消上一个扫描任务
3. 全量模式先清空该库歌曲；增量模式将库内 filePath → {id, modifiedAt} 映射传给 Worker
4. Worker 递归找文件（每 100 个上报一次进度）→ 按批（20 个）并行解析，mtime 未变跳过
5. Worker 返回歌曲数组、失败清单、跳过数 → 主进程事务批量 upsert（按 filePath 判重、mtime 判变）
6. 完成事件携带统计（新增/更新数、跳过数、失败数）推送前端，前端强制重载歌曲并刷新库列表
7. 取消：发取消消息 → Worker 停止解析返回已收集结果 → 宽限期后未退出则强制 terminate

### 数据流和状态流

- 创建：目录 → 文件列表 → 元数据 → 歌曲对象 → 事务写入
- 变更：增量模式以 mtime 为判据，未变文件复用已有记录
- 删除：全量重扫先清空该库记录
- 状态：扫描状态机（starting/finding_files/parsing_metadata/saving_to_db/complete/canceled/error），代次自增标识每次新任务

### 异常、并发与任务规则

- Worker 异常退出（非取消）视为扫描失败并上报
- 目录读取失败记录到失败清单继续遍历；解析失败记录路径与原因
- 代次校验贯穿所有延迟回调（超时、退出、取消），新扫描启动后旧回调一律忽略
- 单任务互斥：已有扫描进行时新请求被拒绝；新扫描启动前自动取消旧扫描

### 关键技术选择

- 使用 Worker 线程隔离解析耗时，避免阻塞主进程 IPC 与窗口交互
- 批量 upsert 与增量 mtime 判断复用歌曲仓库既有能力，扫描模块不另写 SQL

## 3. 数据库的设计

数据库：SQLite（`llmusic.db`），WAL 模式，连接与建表 DDL 集中在数据库连接层。本模块只写 `songs` 表，不改表结构。

### 写入字段

扫描产物写入 songs 表：id（UUID）、libraryId、title、artist、album、duration、filePath、fileSize、hasCover（0/1 标记）、hasLyrics、lyrics（提取文本）、modifiedAt（mtime，增量判据）、format、bitrate、sampleRate、channels、year、genre、trackNumber、discNumber、cover（"embedded"/"none"）、addedAt。完整字段定义见本地音乐库模块开发设计。

### 写入语义

- 批量事务 upsert：filePath 唯一键判存在，modifiedAt 不一致才更新
- 全量重扫前置清空：删除该 libraryId 全部记录后写入
- 索引 `idx_songs_libraryId` 支撑按库清空与查询

### 数据生命周期

- 扫描写入的记录由本地音乐库模块消费与维护（删除、校验、标签更新）
- 取消或部分失败不产生中间状态：只有已解析完成的歌曲对象才会进入写入列表
- 无备份与导出需求；重建策略遵循项目规范（删库重建需授权）

## 4. API 接口的设计

本模块不提供 HTTP 接口，公开边界为 Electron IPC + 主进程事件推送。

### IPC 接口

| 通道 | 调用方向 | 入参 | 返回要点 |
|---|---|---|---|
| scan-music-start | 渲染 → 主进程 | `{ libraryId, clearExisting?: boolean }` | `{ count, failedCount }`；已有扫描进行中返回错误 |
| scan-music-cancel | 渲染 → 主进程 | 无 | 取消当前扫描 |
| scan-progress | 主进程 → 渲染（事件） | — | 阶段、进度、消息；完成事件携带 failedFiles/skippedCount |

### 错误边界

- 库不存在、路径不可访问、扫描互斥冲突在处理器显式返回 `{ success: false, error }`
- Worker 严重错误与异常退出经主进程转为 error 阶段上报
- 取消不是错误：返回 `canceled: true`，前端按正常结束处理

### 前端调用关系

- 媒体库 store 统一发起扫描并监听进度事件（监听器全局只注册一次）
- 扫描完成且当前视图为该库时，强制重载歌曲列表并刷新库统计
- 全局扫描进度组件消费 store 中的扫描状态展示遮罩
