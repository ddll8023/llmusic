# 音乐播放模块开发设计

> 本文档针对 LLMusic 中的音乐播放模块，描述该模块的需求、项目内结构与流程、数据库和 API 设计。代码组织见 `doc/项目结构文档.md`，业务定位见 `doc/模块说明文档.md`。

---

## 1. 需求

### 模块目标

音乐播放模块是全部听歌体验的中枢，解决"用户如何连续、可控地收听本地与在线音乐"这一需求。本地与在线歌曲共用同一套播放引擎与状态管理，支持播放模式、歌词联动、桌面歌词状态同步、媒体会话与会话恢复。

### 功能需求

- 用户可播放/暂停、前后切歌、拖动进度、调节音量与静音、切换播放模式（顺序/随机/单曲循环）
- 本地歌曲经自定义音频流协议播放，浏览器不支持的编码自动转码（按文件变更缓存复用）
- 在线歌曲直接加载网络音频地址播放，支持歌单队列与随机播放
- 播放进度按固定间隔上报，驱动歌词行高亮与逐字歌词展示
- 向主进程推送 NowPlaying 完整快照与位置锚点，供桌面歌词窗口消费
- 集成系统媒体会话：媒体键控制（播放/暂停/上一首/下一首）、锁屏封面展示
- 会话恢复：应用重启后恢复上次播放的本地歌曲、进度、音量与队列
- 播放计数：歌曲完整播放结束后次数 +1（单曲循环也计数，每首每会话一次）
- 播放错误统一捕获并反馈，不静默失败

### 非功能需求

- 播放状态全部收编进统一状态 store，不新增全局可变变量
- 在线歌曲不跨会话持久化（播放地址会过期失效）
- 进度上报间隔 100ms，支撑逐字歌词高亮；桌面歌词位置同步约 5Hz 节流 + RAF 插值
- 切歌触发的 AbortError 属正常流程，不视为错误上报

### 当前范围与明确不做项

- 不负责文件扫描、下载与标签编辑
- 本地与在线仅音源地址不同，引擎与状态完全统一；不维护两套播放实现
- 音量与播放模式等偏好随播放状态持久化，不单独设置项

### 与其他模块的职责边界

- 依赖本地音乐库（歌曲数据与播放计数写入）、歌词管理（进度驱动展示）
- 被在线音乐搜索、QQ 音乐歌单、本地播放列表、窗口与 UI 壳（播放控制栏、桌面歌词窗口）调用
- 向主进程提供 NowPlaying 快照/位置同步，供桌面歌词窗口消费

### 验收标准

- 本地与在线歌曲均可播放，切歌、seek、音量、三种播放模式行为正确
- 重启应用后本地播放会话恢复（歌曲、进度、队列）
- 桌面歌词窗口能随切歌/暂停/seek 正确同步当前句与位置
- 媒体键可控制播放；完整播放后播放计数 +1
- 无法播放的编码经转码后可正常播放

## 2. 该项目的模块结构与流程

### 项目级模块关系

```
本地音乐库 ──歌曲数据──> 音乐播放 <──播放队列── 本地播放列表
歌词管理 <──进度── 音乐播放 ──音源──> 在线音乐搜索 / QQ 音乐歌单
      └──展示──> 窗口与 UI 壳（播放控制栏）
      └──NowPlaying──> 主进程 ──广播──> 桌面歌词窗口
```

### 当前代码边界

- 渲染层引擎：统一音频引擎（单 HTML5 Audio 实例，回调接口：ended/timeupdate/durationchange/error，100ms 定时上报）
- 渲染层状态：播放 store（本地队列 + 在线队列双通道、播放模式、音量、进度、会话持久化、NowPlaying 同步）
- 主进程协议层：`llmusic://audio/<songId>` 自定义协议（Range 分段响应、转码缓存）
- 主进程与渲染协作：媒体会话在播放控制栏组件中接入（navigator.mediaSession）；桌面歌词同步经 `now-playing-update` / `now-playing-position` IPC 推送主进程

### 核心业务流程

1. 播放本地歌曲：设置当前歌曲与队列 → 引擎加载 `llmusic://audio/<songId>` → 主进程按 ID 查库、按 Range 流式返回 → 不支持格式先转码缓存
2. 播放在线歌曲：组装在线队列（歌曲 + URL）→ 引擎直接加载 URL → 按 songMid 异步加载在线歌词
3. 播放结束：单曲循环 → 重新播放并计数；否则按模式取下一首（随机模式走洗牌队列，跳过无地址的在线条目）
4. 会话恢复：启动时从 localStorage 恢复本地播放状态 → 校验歌曲仍存在 → 装载音源不自动播放、恢复进度
5. 进度驱动歌词：100ms 上报 → 更新当前时间 → 按行时间戳推进歌词索引（含偏移量）
6. 桌面歌词同步：切歌/歌词变化时推送完整 NowPlaying 快照；播放中约 5Hz 推送位置锚点 → 主进程广播 → 桌面歌词窗口 RAF 插值

### 数据流和状态流

- 创建：歌曲/在线条目 → 播放队列 → 引擎加载
- 持久化：本地播放状态序列化到 localStorage（playerState）；在线状态不持久化
- 失效：登出清理在线队列与播放；歌曲删除后启动校验过滤队列
- 状态：currentSong/playing/currentTime/duration/playMode + 在线通道（onlinePlayQueue/Index/Shuffle）
- 桌面歌词同步：主渲染进程 → 主进程 NowPlayingSnapshot → 桌面歌词窗口

### 异常、并发与任务规则

- 引擎错误（加载失败/播放失败）置播放错误状态并停止播放，经全局通知反馈
- 切歌竞态：引擎只保留当前 src，AbortError 忽略；歌词加载按 songMid 校验防串歌
- 播放计数防重复：每曲每会话仅计一次（hasBeenCounted 标记）
- 会话恢复的歌曲校验与队列过滤在启动阶段异步完成

### 关键技术选择

- 自定义协议 + Range 流式传输，seek 依赖 206 分段响应
- 转码缓存键为 (songId, mtime)，源文件变更自动失效并清理旧缓存
- 播放状态持久化用 localStorage 而非数据库（纯前端偏好，主进程无需感知）
- 桌面歌词同步用低频位置锚点 + RAF 插值，避免高频 IPC

## 3. 数据库的设计

本模块不直接持久化数据，但依赖 songs 表与两个数据接口：

- 读取：按 songId 查询歌曲记录（filePath、duration、playCount 等），经主进程歌曲仓库
- 写入：播放计数 +1（incrementPlayCount，事务内 UPDATE）
- 会话恢复数据存于渲染进程 localStorage（playerState 键），不属于数据库职责
- 转码缓存：主进程 userData 目录下的转码文件（键含 songId 与 mtime），由播放按需生成与清理，非数据库数据
- 数据生命周期：转码缓存随源文件变更失效；播放计数随歌曲记录生命周期

## 4. API 接口的设计

本模块的公开边界为自定义协议（主进程 → 渲染进程的媒体流）与 IPC 数据接口。

### 自定义音频流协议

| 项 | 说明 |
|---|---|
| URL 形态 | `llmusic://audio/<songId>` |
| 调用方向 | 渲染进程 HTML5 Audio → 主进程协议处理器 |
| 语义 | 主进程按 songId 查库取文件；支持 HTTP Range（206），不支持格式转码为 mp3 后响应 |
| 错误 | 歌曲/文件不存在返回 404；异常返回 500，不泄露路径细节 |

### IPC 接口

| 通道 | 调用方向 | 入参 | 返回要点 |
|---|---|---|---|
| get-song-by-id | 渲染 → 主进程 | songId | 歌曲完整记录（播放恢复校验用） |
| increment-play-count | 渲染 → 主进程 | songId | 更新后的歌曲记录 |
| now-playing-update | 主渲染 → 主进程 | track/lyric/position/playing/speed/lyricOffsetMs/showTranslation/showRoma | 更新完整快照并广播桌面歌词窗口 |
| now-playing-position | 主渲染 → 主进程 | position/playing/speed | 更新位置锚点并广播桌面歌词窗口 |

### 媒体会话（渲染进程内）

- 播放控制栏组件注册 navigator.mediaSession 动作（播放/暂停/上一首/下一首），状态变化时更新媒体元数据（标题、歌手、封面）
- 不涉及 IPC；动作直接映射播放 store action

### 错误边界

- 播放地址缺失的在线条目在队列推进时跳过
- 引擎错误统一进入播放错误状态并经全局通知反馈，不抛出未捕获异常
- 转码失败返回错误并由引擎触发错误回调，用户可见提示

### 前端调用关系

- 各业务模块经播放 store 的公开 action 发起播放（playSong/playOnlineSong/playSongFromList）
- 组件不直接操作引擎实例；引擎仅由播放 store 接线
- 播放 store 通过 `syncNowPlayingToMain` / `syncNowPlayingPosition` 向主进程同步桌面歌词数据
