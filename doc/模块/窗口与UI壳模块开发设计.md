# 窗口与 UI 壳模块开发设计

> 本文档针对 LLMusic 中的窗口与 UI 壳模块，描述该模块的需求、项目内结构与流程、数据库和 API 设计。代码组织见 `doc/项目结构文档.md`，业务定位见 `doc/模块说明文档.md`。

---

## 1. 需求

### 模块目标

窗口与 UI 壳模块是应用的容器与基础交互框架，解决"用户如何稳定地操作这个桌面应用"这一需求。它承载窗口生命周期、侧边栏导航、标题栏、托盘、统一歌曲表格、播放控制栏与后端子进程管理。

### 功能需求

- 无边框窗口控制：最小化/最大化/还原/关闭，标题栏拖拽与双击最大化，最大化状态同步
- 侧边栏导航：平台导航（动态注册）、本地音乐入口、开发者日志入口（受开发者模式控制）、可折叠与拖拽调宽
- 系统托盘：显示主界面、退出；macOS 关闭窗口仅隐藏，激活事件重建窗口；单实例锁（二次启动聚焦已有窗口）
- 统一歌曲表格：本地/在线双模式、全模式虚拟滚动、封面队列加载、排序、右键菜单、批量选择
- 播放控制栏：播放控制、进度/音量、封面、歌词入口、媒体会话；空闲自动收缩，收缩态可拖拽定位
- 后端子进程管理：启动、健康检查等待就绪、退出优雅停止（超时强制终止）；开发模式由 dev-runner 托管
- 文件关联打开：系统文件关联或命令行参数打开音频文件时聚焦并播放
- 退出清理：IPC 卸载、扫描任务终止、托盘销毁、数据库关闭，全部幂等
- 窗口关闭行为：退出应用或最小化到托盘（可配置）

### 非功能需求

- 清理逻辑幂等可重入，任何退出路径安全调用
- 主进程不承载业务逻辑，只提供容器、导航与交互框架
- 播放控制栏不直接持有引擎，全部经播放 store
- 窗口资源（托盘、IPC、worker）随退出路径释放

### 当前范围与明确不做项

- 不实现页面业务（页面归属各业务模块）
- 不做多窗口（仅主窗口 + 全屏歌词页在窗口内切换）
- 不承载权限与安全边界（本地应用无账号体系）

### 与其他模块的职责边界

- 依赖全局通知（反馈出口）、音乐播放（控制栏状态）
- 被全部页面组件依赖（容器与导航）
- 后端子进程管理依赖后端服务的 HTTP 健康接口

### 验收标准

- 窗口控制全平台（win/mac）行为正确；macOS 关闭隐藏、Cmd+Q 退出
- 二次启动聚焦已有窗口；文件关联打开能播放目标文件
- 应用退出后无残留进程（后端子进程、扫描 worker）
- 统一歌曲表格在千首歌曲列表下滚动流畅

### 范围外事项

- 多窗口/独立迷你播放器当前未实现
- settings 表处于闲置状态（事实）：若后续将偏好迁移至数据库，需补充 IPC 读写通道并评估 localStorage 存量数据迁移

## 2. 该项目的模块结构与流程

### 项目级模块关系

```
全部业务页面 ──> 窗口与 UI 壳 <──播放状态── 音乐播放
                    │
                    └──健康检查──> 后端服务（FastAPI）
```

### 当前代码边界

- 主进程入口：生命周期（单实例、activate、will-quit）、后端进程管理（spawn/健康轮询/停止）、窗口创建、托盘、文件打开
- 主进程窗口处理器：窗口控制、目录选择、系统对话框、剪贴板、关闭行为读写
- 渲染层 UI 状态：UI store（侧边栏可见性/宽度、当前视图、关闭行为、播放栏收缩、性能模式、开发者模式）
- 渲染层壳组件：标题栏、侧边栏、播放控制栏、全局扫描进度、Toast 容器
- 渲染层统一表格：歌曲表格（本地/在线双模式、虚拟滚动、封面队列）
- 共享工具：拖拽辅助（节流/边界钳制）、侧边栏拖拽调整

### 核心业务流程

1. 应用启动：单实例检查 → 后端子进程启动与健康等待（或 dev-runner 托管跳过）→ 数据库初始化 → 注册音频协议 → 托盘与窗口创建 → IPC 注册 → 启动文件校验（异步）
2. 窗口控制：标题栏按钮 → IPC → 主进程窗口操作 → 状态事件回推（最大化变化）
3. 托盘与关闭：关闭窗口按平台与配置行为处理（mac 隐藏 / 最小化到托盘 / 退出）；托盘菜单退出走完整清理
4. 文件打开：命令行/文件关联 → 二次实例或激活路径 → 校验扩展名 → 推送渲染进程 → 聚焦播放
5. 退出：任一退出路径 → 幂等清理（IPC 卸载、扫描终止、托盘销毁、数据库关闭）→ 停止后端进程（优雅 3 秒超时强杀）

### 数据流和状态流

- 窗口状态：主进程持有（appState），经 IPC/事件与渲染层双向同步
- UI 偏好：渲染层 localStorage（侧边栏可见性、播放栏行为）；关闭行为经 IPC 与主进程内存同步
- 视图切换：UI store currentView 驱动页面容器渲染，离开播放队列视图时清理歌单临时状态；开发者日志视图入口由开发者模式控制
- 后端状态：主进程内存（running/status/pid），异常仅日志，不弹窗

### 异常、并发与任务规则

- 后端启动失败不阻塞应用（在线能力降级），状态记录于主进程
- 退出清理幂等（cleanupDone 标记）；扫描 worker 终止为兜底双保险
- 健康检查轮询带超时（15 秒）与间隔（300ms）
- 单实例锁失败（已存在实例）时聚焦已有窗口并退出本实例

### 关键技术选择

- 无边框窗口 + 自定义标题栏，最大化状态经事件双端同步
- 自定义协议注册在 app ready 前完成（特权声明要求）
- 后端托管区分打包模式（extraResources 可执行）与开发模式（.venv python -m uvicorn）

## 3. 数据库的设计

本模块不直接新增表结构与业务数据，与数据库的关联：

- 启动阶段初始化数据库连接（建表 DDL 幂等），退出时关闭连接
- 文件校验（歌曲存在性）启动后异步执行，结果写回 songs 表（复用本地音乐库能力）
- settings 表当前无调用方（事实）：关闭行为等偏好实际存于渲染层 localStorage 与主进程内存，未使用 settings 表
- 数据生命周期：数据库随应用用户数据目录，退出仅关闭连接不删数据；删库重建需授权

## 4. API 接口的设计

本模块的公开边界为 Electron IPC 与主进程事件。

### 窗口控制 IPC（渲染 → 主进程）

| 通道 | 说明 |
|---|---|
| window-minimize / window-maximize / window-restore / window-close / window-show | 窗口操作 |
| is-window-maximized | 查询最大化状态 |
| window-maximized-change | 主进程 → 渲染事件，最大化状态变化推送 |
| set-close-behavior / get-close-behavior | 关闭行为读写（主进程内存持有） |

### 系统能力 IPC（渲染 → 主进程）

| 通道 | 说明 |
|---|---|
| select-directory | 目录选择对话框 |
| show-open-dialog | 文件选择对话框 |
| show-item-in-folder | 资源管理器定位文件（绝对路径 + 存在性校验） |
| copy-to-clipboard | 剪贴板写入 |
| open-audio-file | 主进程 → 渲染事件，外部文件打开通知 |

### 错误边界

- 窗口不存在、路径非法、关闭行为无效显式返回 `{ success: false, error }`
- 对话框取消返回 canceled，不计为错误
- 主进程异常统一捕获，不向渲染层透出堆栈

### 前端调用关系

- 壳组件经 `window.electronAPI` 调用窗口能力；UI store 统一持有布局与偏好状态
- 页面组件注册进侧边栏导航（平台注册配置 + 视图切换机制）；开发者日志入口按开发者模式显示
- 播放控制栏经播放 store 订阅状态，不直接操作引擎
