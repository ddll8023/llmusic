# 本地音乐库模块开发设计

> 本文档针对 LLMusic 中的本地音乐库模块，描述该模块的需求、项目内结构与流程、数据库和 API 设计。代码组织见 `doc/项目结构文档.md`，业务定位见 `doc/模块说明文档.md`。

---

## 1. 需求

### 模块目标

本地音乐库是本地音乐功能的数据底座，解决"用户如何组织、浏览和管理自己磁盘上的音乐"这一需求。它管理歌曲的元数据记录与音乐库（目录集合）归属关系，并对外提供歌曲的查询、导入、删除和播放计数能力。

### 功能需求

- 用户可创建多个音乐库（每个音乐库对应一个本地目录），并可重命名、删除音乐库
- 用户可按当前音乐库浏览歌曲，也可浏览全部歌曲；支持按标题/歌手/专辑关键词过滤、按属性排序
- 用户可从本地磁盘选择音频文件直接导入音乐库（新增或按文件变更更新已有记录）
- 用户可删除歌曲（同时从所有歌单中移除引用），删除失败时给出文件清理警告
- 歌曲播放完成后播放次数 +1，并在界面与数据库中同步
- 应用启动时后台校验库内文件是否存在、是否被修改，缺失记录自动清理，变更文件自动重新解析
- 大列表场景使用虚拟滚动渲染，封面按受限并发队列异步加载

### 非功能需求

- 歌曲列表加载需带请求序号与库标识，防止切库时旧响应覆盖新数据
- 同一库的并发加载请求应去重（复用进行中的 Promise）
- 路径类入参必须经安全校验（绝对路径 + 扩展名白名单）
- 数据库写入使用事务批处理，单文件失败不中断整批

### 当前范围与明确不做项

- 不负责文件扫描（归音乐扫描模块）；扫描入库结果由本模块展示
- 不负责音频解码播放（归音乐播放模块）
- 不负责歌曲标签、封面的编辑（归标签与封面模块）；本模块只消费其更新结果

### 与其他模块的职责边界

- 上游：音乐扫描模块写入歌曲；标签与封面模块更新歌曲记录；音乐下载模块落盘的文件经导入能力入库
- 下游：音乐播放模块读取歌曲数据播放；本地播放列表模块读取歌曲数据组单

### 验收标准

- 创建音乐库后可立即扫描并展示歌曲，切库后列表数据与库一致
- 导入重复文件不产生重复记录，变更文件按 mtime 更新
- 删除歌曲后歌单中不再包含该歌曲
- 启动校验后，失效记录自动移除且界面同步

## 2. 该项目的模块结构与流程

### 项目级模块关系

```
音乐扫描 ──写入──> 本地音乐库 <──更新── 标签与封面
音乐下载 ──导入──>     │
                      │ 读取
                ┌─────┴──────┐
           音乐播放        本地播放列表
```

### 当前代码边界

- 渲染层：`useMediaStore`（歌曲/库列表状态、加载去重、请求竞态、扫描联动）
- 主进程 IPC 层：歌曲处理器（查询、导入、删除、播放计数）、音乐库处理器（库 CRUD，含扫描中禁止删除校验）
- 数据访问层：歌曲仓库（解析、批量 upsert、删除、文件校验）、音乐库仓库（库 CRUD 与歌曲数聚合）；统一经数据库门面导出
- 数据库：better-sqlite3 单例，WAL 模式，prepared statement 缓存

### 核心业务流程

1. 用户创建音乐库 → 选择目录 → 写入库表 → 自动触发扫描（关联音乐扫描模块）
2. 用户切换音乐库 → 按库 ID 查询歌曲 → 请求带递增序号，过期响应丢弃 → 列表渲染（虚拟滚动）
3. 用户导入文件 → 逐个解析元数据（含歌词/封面标记）→ 事务批量 upsert（filePath 唯一，mtime 相同跳过）
4. 删除歌曲 → 事务内先清歌单关联并刷新歌单更新时间，再删歌曲记录 → 尝试删除磁盘文件与同目录 .lrc，失败给出警告
5. 启动时校验 → 遍历全部歌曲，缺失删除、mtime 变更重新解析 → 事务应用变更

### 数据流和状态流

- 创建：文件 → 元数据解析 → songs 表
- 流转：歌曲记录更新（标签编辑、播放计数、文件校验）→ 前端定点替换或按库重载
- 删除：songs 行 + playlist_songs 关联 +（尽力）磁盘文件
- 前端状态：`songs` 数组与 `songsLoadedLibraryId` 配对，保证展示数据与来源库一致

### 异常、并发与事务规则

- 批量写入使用 `better-sqlite3` 事务包装，单条失败记入失败清单不中断
- 删除歌曲与清歌单关联在同一事务内完成
- 加载请求以递增序号丢弃过期响应；同库并发加载复用同一 Promise
- 扫描进行中禁止删除/清空/导入，避免数据竞争

### 关键技术选择

- 使用 better-sqlite3（主进程同步访问，事务 API 原生支持），索引保证按库查询性能
- 歌曲批量 upsert 以 filePath 唯一 + modifiedAt 判变更，天然支持增量场景

## 3. 数据库的设计

数据库：SQLite（`llmusic.db`，位于统一的 Electron `userData` 数据目录），WAL 模式。连接与建表 DDL 集中在数据库连接层，本模块读写 `songs` 与 `libraries` 两张表。

### songs 表（歌曲记录）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | TEXT | PRIMARY KEY | UUID |
| filePath | TEXT | NOT NULL UNIQUE | 文件绝对路径，批量 upsert 的判重键 |
| libraryId | TEXT | 可空 | 所属音乐库；空表示未归属 |
| title / artist / album / albumArtist | TEXT | NOT NULL（前三个） | 歌曲名/歌手/专辑，解析失败用"未知"兜底 |
| year | INTEGER | 可空 | 发行年份 |
| duration | REAL | NOT NULL DEFAULT 0 | 时长（秒） |
| fileSize | INTEGER | 可空 | 字节数 |
| hasCover / hasLyrics | INTEGER | NOT NULL DEFAULT 0 | 是否内嵌封面/歌词（0/1） |
| lyrics | TEXT | 可空 | 提取的歌词文本 |
| modifiedAt | INTEGER | 可空 | 文件 mtime（毫秒），增量判变依据 |
| format / bitrate / sampleRate / channels | TEXT/REAL/INTEGER/INTEGER | 可空 | 音频格式信息 |
| playCount | INTEGER | NOT NULL DEFAULT 0 | 播放次数 |
| cover | TEXT | 可空 | 封面标记（扫描产物 "embedded"/"none"） |
| fileExists | INTEGER | 可空 | 文件存在性标记（启动校验产物） |
| genre / trackNumber / discNumber | TEXT/INTEGER/INTEGER | 可空 | 流派/音轨号/碟片号 |
| addedAt | TEXT | 可空 | 入库时间（ISO） |

### libraries 表（音乐库）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | TEXT | PRIMARY KEY | UUID |
| name | TEXT | NOT NULL | 库名称 |
| path | TEXT | NOT NULL | 扫描目录绝对路径 |
| createdAt | TEXT | NOT NULL | 创建时间（ISO） |

### 索引与查询

- `idx_songs_libraryId`（libraryId）：按库加载歌曲的查询路径
- filePath 唯一索引：批量 upsert 的存在性检查
- 歌曲数统计：库列表查询中按 libraryId 聚合 COUNT

### 实体关系与生命周期

- 音乐库 1:N 歌曲（libraryId 外键语义，但未声明物理外键约束——歌曲可无库归属）
- 删除音乐库仅删库记录，不删歌曲（前端按库过滤展示）；歌曲删除会连带清除歌单引用
- 歌曲记录的生命周期：扫描/导入创建 → 标签编辑/播放计数/文件校验更新 → 删除或启动校验清理

### 事务与一致性

- 批量 upsert、删除歌曲（含歌单清理）各自为一个事务
- 写入与读取均为主进程同步执行，单连接串行化，WAL 保证读写不互斥

### 结构变更策略

后续 SQLite DDL 结构变更按当前建表定义处理；如需删除 `llmusic.db` 重建并重新扫描，必须先提供数据库路径与影响范围并获得授权。

## 4. API 接口的设计

本模块不提供 HTTP 接口，公开边界为 Electron IPC（渲染进程 → 主进程），经 preload 暴露为 `window.electronAPI` 方法，统一返回 `{ success, ... }` 结构，错误为 `{ success: false, error }`。通道名集中在 IPC 通道常量文件中声明。

### 歌曲相关 IPC

| 通道 | 调用方向 | 入参 | 返回要点 |
|---|---|---|---|
| get-songs | 渲染 → 主进程 | `{ libraryId?: string }`（"all" 表示全部） | `{ songs }` |
| get-song-by-id | 渲染 → 主进程 | `songId` | `{ song }` |
| parse-song-from-file | 渲染 → 主进程 | `filePath` | `{ song }`；路径须通过扩展名白名单校验 |
| import-music-files | 渲染 → 主进程 | `filePaths: string[]` | `{ importedCount, updatedCount, failedFiles, message }`；扫描中禁止 |
| increment-play-count | 渲染 → 主进程 | `songId` | `{ song }`（更新后记录） |
| delete-song | 渲染 → 主进程 | `songId` | `{ deletedSong, removedFromPlaylists, warning? }`；扫描中禁止 |
| clear-all-songs | 渲染 → 主进程 | 无 | 清空全部歌曲并清封面缓存；扫描中禁止 |

### 音乐库相关 IPC

| 通道 | 调用方向 | 入参 | 返回要点 |
|---|---|---|---|
| get-libraries | 渲染 → 主进程 | 无 | `{ libraries }`（含 songCount 聚合） |
| add-library | 渲染 → 主进程 | `{ name?, dirPath }` | `{ library }`；目录须存在 |
| update-library | 渲染 → 主进程 | `{ libraryId, updates }` | `{ library }` |
| remove-library | 渲染 → 主进程 | `libraryId` | 删除库记录；扫描中禁止 |
| select-directory | 渲染 → 主进程 | 无 | 系统目录选择对话框结果 |

### 错误边界

- 主进程层捕获异常统一转为 `{ success: false, error }`
- 业务约束（扫描中操作、库不存在、路径非法）在处理器内显式返回错误，不抛未处理异常
- 前端统一错误反馈走全局通知模块；凭证类错误不适用于本模块（纯本地）

### 前端调用关系

- 全部经 `window.electronAPI` 调用，不直接创建 IPC 通道
- 渲染层 store 负责请求去重、竞态丢弃与状态更新；组件不直接调用 IPC
