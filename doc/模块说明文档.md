## 1. 文档定位

本文档面向参与 LLMusic 开发的开发者，帮助理解系统的业务功能设计、各模块的职责边界以及典型业务流程。阅读建议：先通读第 2-4 节建立整体认知，再按需查阅第 5 节的具体模块说明。

## 2. 系统功能定位

LLMusic 是一个**桌面本地音乐播放器**，同时提供**在线音乐发现与下载**能力。系统围绕以下核心能力方向设计：

| 能力方向 | 业务目标 | 用户价值 |
|---------|---------|---------|
| 本地音乐管理 | 组织、浏览、管理本地音频文件 | 建立个人音乐库 |
| 在线音乐发现 | 搜索 QQ 音乐曲库、获取下载链接 | 扩展音乐收藏 |
| 音乐播放体验 | 高质量音频播放、歌词同步、播放模式控制 | 沉浸式听歌 |
| 歌单与收藏 | 创建和管理播放列表 | 按主题组织音乐 |
| 元数据维护 | 编辑歌曲标签、管理封面 | 保持音乐库整洁 |

## 3. 端侧职责划分

| 端侧 | 职责定位 | 设计关注点 |
|------|---------|-----------|
| Electron 主进程 | 桌面壳层、IPC 桥接、本地数据持久化、`llmusic://` 音频流协议与转码、文件系统操作 | 窗口生命周期、进程管理、数据一致性、路径安全校验 |
| **Vue 渲染进程（TypeScript）** | UI 渲染、用户交互、状态管理、统一音频引擎、在线 API 调用 | 组件化、类型安全、状态响应式、体验流畅度 |
| FastAPI 后端 | 在线音乐业务逻辑层，代理 qqmusic-api 的 HTTP 封装（**仅官方模块使用**） | 接口幂等性、错误码统一、凭证管理、全局异常兜底 |
| 本地数据库 (SQLite / better-sqlite3) | 单文件数据库 `userData/llmusic.db`（WAL 模式），存储歌曲/歌单/音乐库/设置 | 读写性能、数据完整性（无迁移设计，旧 db.json 自动删除） |
| QQ Music SDK | 外部 SDK，提供 QQ 音乐搜索、下载、登录、凭证刷新等底层能力 | SDK 版本兼容、异常隔离 |

## 5. 各业务模块说明

### 5.1 本地音乐库

**定位**：系统的数据核心层，管理所有本地歌曲的元数据和音乐库组织结构。

**核心功能**：音乐库 CRUD、歌曲数据加载、搜索过滤、播放计数、导入/删除。

**数据层（v3）**：持久化由 lowdb（JSON 全量读写）迁移为 better-sqlite3。`db.ts` 维护连接单例（WAL 模式）与建表 DDL，按实体拆分 songRepo / libraryRepo / playlistRepo / settingsRepo 四个仓库，`Database.ts` 作为聚合门面 re-export 各仓库函数，保持既有调用契约不变；prepared statement 按 SQL 文本缓存复用，songs 表按 libraryId 建索引。

**性能优化（v2）**：
- **按库加载与去重**：按 `activeLibraryId` 请求当前库歌曲（`getSongs({ libraryId })`），store 层通过 `songsLoadedLibraryId` / `songsLoadingLibraryId` / `songsLoadRequestId` 机制去重，相同库不会重复 IPC，快速切库时旧请求不再覆盖新结果
- **虚拟滚动**：配合 BaseSongTable 使用 RecycleScroller 虚拟滚动，恒定 DOM 节点数；表格体仅 `overflow-hidden`，唯一滚动宿主为 RecycleScroller，避免双滚动条导致高度计算异常
- **封面队列加载**：封面通过队列按需加载，最多并发 2 个 IPC，失败封面在组件生命周期内缓存（`failedCoverIds`），避免无封面歌曲反复触发 `music-metadata parseFile`；组件卸载时自动清理 pending 队列

### 5.2 在线音乐搜索（官方模块）

**定位**：连接 QQ 音乐曲库的发现入口，提供关键词和链接两种搜索方式。

**核心功能**：关键词搜索、链接搜索、专辑封面获取、试听入口。

**性能优化（v2）**：
- **搜索缓存**：翻页结果缓存到 `searchCache`（Map<页码, 数据>），回看已翻过的页秒开，无需重新请求后端
- **懒加载**：翻页时先展示搜索结果（骨架屏占位），封面和播放 URL 异步补全，不阻塞页面渲染
- **统一分页组件**：使用 `PaginationBar` 组件替代内联分页栏，可复用

**设计边界**：
- 搜索结果统一展示在 [官方] Tab
- 搜索结果中的下载链接只返回 URL，不触发下载
- 封面 URL 是静态拼接结果
- API 调用全部经 `api/qqmusic.ts` 强类型入口（`ApiResponse<T>`），业务失败抛出携带错误码的 `ApiError`，错误经全局 Toast 反馈（见 §5.12）

### 5.3 音乐下载（官方模块）

**定位**：将从 QQ 音乐获取的音频文件保存到用户本地磁盘，并自动写入元数据。

**核心功能**：单曲下载、批量下载、下载状态管理、元数据嵌入。

**渲染层（`useDownloadManager` composable）**：单曲与批量下载的共享逻辑，供 discover 与 qqmusic 两个 store 复用；批量下载并发上限 3（与主进程侧限流一致），维护逐曲进度（pending/downloading/success/failed）；元数据包获取失败时降级为裸下载。

**主进程（`downloadHandlers.ts`）**：
- 主进程侧并发上限 3（不信任渲染层限流），网络失败自动重试 2 次
- 临时文件以 `randomUUID` 命名，流式写盘（stream pipeline），避免大文件占用内存
- MP3 使用 node-id3 写入 ID3v2.4 标签（含 USLT 歌词/APIC 封面）；FLAC 使用 ffmpeg 写入 Vorbis Comment 标签与封面（`attached_pic`）
- 元数据写入失败时**降级保留纯音频文件**，warning 信息透传到前端 Toast
- 目标文件名经 `isSafeFilename` 防路径逃逸校验

**设计边界**：
- 不参与下载链接的获取逻辑（由在线搜索模块完成）
- 元数据获取通过后端 `/song/download-bundle` 接口一次性聚合（后端三段请求 `asyncio.gather` 并行）

### 5.4 QQ 音乐登录

**定位**：管理 QQ 音乐登录认证，为在线搜索和下载提供凭证支持。

**核心功能**：二维码登录、登录状态管理、凭证持久化与自动刷新。

**凭证管理设计**：
- 凭证加载带 **mtime 缓存**（文件未变化不重复读盘解析），写盘采用**原子写**（临时文件 + 替换）
- **自动刷新**：应用 lifespan 启动时与 `/auth/status` 查询时触发 SDK `refresh_credential`，刷新成功后更新 Client 单例并落盘
- 前端收到 2001（未登录）/ 2002（凭证过期）错误码时**自动同步登录状态**（auth store 复位）

### 5.5 音乐播放

**定位**：核心播放引擎，本地与在线歌曲使用**同一套 HTML5 Audio 统一引擎**。

**核心功能**：播放/暂停/seek、播放模式切换（顺序/随机/单曲循环）、媒体会话集成、播放状态管理。

**播放链路（v3）**：
- 渲染层统一引擎 `core/audio/engine.ts`：单个 HTMLAudioElement 驱动本地与在线播放，对外提供 load/play/pause/seek/音量等统一控制接口，进度以 100ms 定时上报（满足歌词逐字高亮频率）
- **本地歌曲**：经 `llmusic://audio/<songId>` 自定义协议流式播放。主进程 `audioProtocol.ts` 按 songId 查库并做 **Range 分段响应**；Chromium 不支持的格式（如部分编码）用 ffmpeg 转码为 mp3，结果按文件 mtime 缓存到 `userData/transcode-cache` 复用
- **在线歌曲**：直接使用 HTTP URL 加载
- 不再使用 Web Audio API + PCM 数据 IPC 传输，`playerHandlers.ts` 与 `player-*` IPC 通道已不存在

**状态管理（v3）**：播放状态全部收编进 player store（原 `window.sourceNode` / `window.audioContext` 等 19 个非响应式全局变量已消灭），新增 `duration` / `playbackError` / `onlineCoverUrl` 状态；`attachEngine` 在应用启动时把引擎回调（onEnded/onTimeUpdate/onDurationChange/onError）接入 store，`restorePlayback` 负责会话恢复。播放错误统一进入 `playbackError` 并经 Toast 反馈。

### 5.6 歌词管理

**定位**：歌词的获取、解析与同步展示，支持标准 LRC 格式、QQ 音乐 JSON 格式和纯文本格式。

**核心功能**：

1. **歌词获取链路**（`lyricsHandlers.ts → getLyrics`）：
   - 内嵌歌词 LRC 检测 → 解析为 `LyricLine[]`
   - 类 QQ 音乐 JSON 格式检测（`syncText`）→ 提取结构化时间轴
   - **文件回退提取**：当数据库中的歌词为纯文本（入库时丢失时间戳）时，直接使用 `music-metadata` 重新读取音频文件的 VorbisComment LYRICS 标签，提取带时间戳的完整 LRC 歌词
   - 纯文本 fallback：以上均失败时，将歌词文本逐行拆分为无时间戳的歌词行（time = -1）
   - 外部 LRC 文件：若数据库无内嵌歌词，检查同路径 `.lrc` 文件
2. **LRC 解析引擎**（`parseLrc`）：
   - 标准 LRC 时间戳解析（`[mm:ss.xx]` / `[mm:ss:xx]`）
   - 同时间戳多行自动合并翻译（第二行→translation，第三行→roma）
   - 逐字歌词解析（`<mm:ss.xx>字` 格式 → `LyricWord[]`）
3. **LRC 检测正则**：`/\[\d{2}:\d{2}[\.:]\d{2,3}\]/`，同时支持 `.` 和 `:` 作为毫秒分隔符
4. **共享提取模块**（`sys_electron/utils/lyrics.ts`）：ID3v2 USLT / VorbisComment LYRICS / common.lyrics（含 syncText 时间戳重建）/ 同目录 `.lrc` 四条提取路径的**唯一实现**，扫描（ScannerWorker）、歌词获取（lyricsHandlers）、标签读取（tagHandlers）共用

**性能优化（v3）**：
- 歌词解析结果按 songId 做 LRU 缓存（上限 200 条，仅缓存成功结果）
- 标签写回可能改写歌词后调用 `invalidateLyricsCache` 使对应缓存失效

**设计边界**：
- 歌词存储优先保持原始文本格式（LRC / JSON / plain text）
- 存量数据（之前已入库的歌曲）歌词为纯文本时，播放时自动从音频文件重新提取带时间戳的歌词，无需重新扫描音乐库

**关联模块**：
- ScannerWorker.ts（音乐扫描时经 utils/lyrics.ts 提取歌词并入库）
- LyricPage.vue（歌词全屏展示页面）
- PlayerBar.vue（歌词入口按钮）

### 5.6a LyricPage 封面区域动画增强

**定位**：LyricPage 左侧专辑封面区域的视觉特效系统，播放时提供沉浸式黑胶唱片风格的动态展示。

**核心功能**：

1. **黑胶唱片旋转**（`vinylSpin` / `coverSpin`）：唱盘（4s/圈）与封面（8s/圈）以不同速度持续旋转，播放时运行，暂停时静止
2. **声波波纹环**（`rippleExpand`）：3 层错开延迟的同心波纹环从封面扩散，伴随内外 box-shadow 辉光
3. **旋转渐变发光边框**（`borderSpin`）：双圈 conic-gradient 渐变环，内圈 6 色、外圈 4 色反向旋转，常态慢转（6s），播放加速（2s），多层 glow 阴影（10px∼80px）
4. **玻璃反光扫光**（`shineSweep`）：720° 旋转扫光反射覆盖封面，透明度从 0→0.8→0 循环
5. **浮动彩色粒子**（`particleFloat`）：8 个随机位置/大小/颜色的发光粒子缓慢上升漂移，切歌重新随机
6. **声波可视化条**（`waveBounce`）：20 根交叠跳动的高度动画条，播放时有歌词时激活
7. **封面色彩提取**（`useAlbumColors` composable）：自动从专辑封面提取主色 → 动态映射到光晕、阴影和边框渐变

**动画触发机制**：
- `playerStore.playing` 控制旋转/扫光/粒子/声波条的 class 切换
- 切歌时 `songKey` ref 自增 → Vue `:key` 强制重挂载动画元素，CSS `@keyframes` 从头开始
- 黑胶唱盘不加 key，保持连续旋转不跳位

**设计要点**：
- 所有动画使用 CSS `@keyframes` 实现，零 JS 动画负担
- CSS 变量 `--album-glow-color` / `--album-accent-color` 由封面颜色动态驱动
- 移动端隐藏粒子和声波条，缩小唱盘/封面尺寸
- 无专辑封面时显示首字母占位图

**性能优化（v3）**：
- **性能模式**：`uiStore.performanceMode` 开启时（Settings 提供开关）关闭装饰性动画（粒子/扫光/波纹等），仅保留基础展示
- **页面隐藏暂停**：页面不可见时暂停动画，避免后台耗电
- **系统偏好适配**：响应 `prefers-reduced-motion`，系统开启减弱动态效果时自动降级

**关联模块**：
- `playerStore.playing`（播放状态，控制动画启停）
- `useAlbumColors` composable（封面色彩提取）
- `uiStore.performanceMode`（性能模式开关）
- `base.css`（通用 `@keyframes spin`、过渡类等基础动画）

### 5.7 播放列表

**定位**：歌曲的主题组织工具，支持用户创建、管理多个播放列表。

**核心功能**：歌单 CRUD、歌曲添加/移除、歌单排序。

**数据结构**：歌单主体存 `playlists` 表，歌曲归属与顺序存 `playlist_songs` 关联表（playlistId + songId 复合主键，position 维护顺序）。

**性能优化（v2）**：
- **并行加载**：加载歌单歌曲时，优先从 `mediaStore.songs` 内存缓存中匹配，未命中部分通过 `Promise.all` 并行 IPC 查询，避免串行逐首请求

### 5.8 音乐扫描

**定位**：将用户本地磁盘中的音频文件扫描入库，解析元数据并提取歌曲信息。

**核心功能**：

1. **目录递归遍历**（`ScannerWorker.ts → findAllAudioFiles`）：支持所有 `SUPPORTED_AUDIO_EXTENSIONS` 格式，按批次报告进度
2. **增量扫描**：非全量重扫时，主进程把库中已有 `{filePath → {id, modifiedAt}}` 映射传给 Worker，**mtime 未变化的文件跳过解析**（复用已有记录），结果中以 `skippedCount` 上报跳过数
3. **元数据解析**（`parseAudioFile` 使用 `music-metadata` 库）：提取标题、艺术家、专辑、时长、码率、采样率、格式、年份、流派、音轨号、碟片号
4. **歌词提取**：调用共享模块 `sys_electron/utils/lyrics.ts`（见 §5.6），按 ID3v2 USLT → VorbisComment LYRICS → common.lyrics（syncText 重建 LRC）→ 同路径 `.lrc` 文件的优先级尝试
5. **封面提取**：解析嵌入式封面图片（`common.picture`），记录为 `"embedded"` 标记
6. **Worker 线程隔离**：扫描在独立 Worker 线程中执行，支持取消操作和实时进度报告
7. **失败文件收集上报**：单个文件解析失败不中断扫描，失败路径与原因收集为 `failedFiles`，随扫描结果以 `failedCount` / `skippedCount` 一并上报到前端展示
8. **批量处理**：按批次（默认 20 个文件一批）使用 `Promise.allSettled` 并行解析

**设计边界**：
- 不修改源文件内容，仅读取元数据
- 扫描结果直接入库，不保留中间状态
- 扫描支持取消，取消后已解析的歌曲仍然入库；每次扫描持有自增 `scanGeneration`，延迟的超时/清理回调必须校验 generation 匹配，**防止误杀后续新扫描的 Worker**

**关联模块**：
- `scanHandlers.ts`（IPC 处理器，进度节流推送）/ `MusicScanner.ts`（Worker 调度）
- `Database.ts`（扫描结果写入 SQLite）
- `GlobalScanProgress.vue`（扫描进度 UI）
- `MusicLibrary.vue` / `MediaStore`（扫描完成后展示结果）

### 5.9 标签与封面

**定位**：歌曲元数据的查看与编辑，支持封面提取与替换。

**核心功能**：ID3 标签读取/写入、封面图片提取、封面替换、歌词标签写入。

**性能优化（v3）**：
- **封面缓存**：主进程按累计 base64 字节数（上限 50MB，而非条目数）淘汰的 LRU 缓存，并含**负缓存**（记录"确认无封面"），避免无封面歌曲反复整文件解析 + 目录探测
- **缓存失效联动**：标签写回可能改写歌词后触发歌词缓存失效（见 §5.6）

**安全边界**：所有文件路径类 IPC 通道入参经 `sanitizePath.ts` 校验（`isAudioPath` 绝对路径 + 扩展名白名单 / `isSafeFilename` 防路径逃逸）后才进入文件系统操作。

**核心功能**：窗口控制（最小化/最大化/关闭）、侧边栏导航、标题栏、系统托盘、全局 UI 状态管理。

**健壮性设计**：

### 5.10b BaseSongTable 统一表格组件

**定位**：唯一的歌曲表格组件（旧版 SongTable 已不存在），**全模式基于 RecycleScroller 虚拟滚动渲染**，通过 props 开关配置差异能力。

### 5.11 PlayerBar 播放控制栏

**定位**：位于屏幕底部的全局播放控制栏，提供播放控制、进度调节、音量调节、歌词入口和播放列表管理功能。

**核心功能**：
1. **播放控制**：播放/暂停、上一首、下一首、播放模式切换（顺序/随机/单曲循环）——全部委托 player store 的 action，音频输出由统一引擎驱动（见 §5.5）
2. **进度调节**：点击/拖动进度条改变播放位置，支持 seek 锁定防止位置回弹
3. **音量调节**：垂直滑块调节音量，支持静音切换
4. **封面显示**：从主进程获取 base64 封面数据，动态加载专辑封面背景光晕；在线歌曲使用 `playerStore.onlineCoverUrl`
5. **歌词入口**：点击封面跳转到歌词展示页面，自动加载歌词
6. **媒体会话集成**：支持系统媒体控制（播放/暂停/上一首/下一首/seek）、锁屏封面展示
7. **自动收缩**：空闲 5 秒后自动收缩为紧凑模式，窗口失焦时自动收缩
8. **收缩态拖拽**：收缩状态下可通过鼠标拖拽在屏幕自由移动位置，松开后固定；展开后自动回到底部居中，会话内记忆拖拽位置（刷新重置）

**设计边界**：
- PlayerBar 不直接持有音频引擎实例，播放状态与控制全部经 player store（无 `window.*` 全局变量）
- 本地与在线播放共用同一引擎与同一套状态管理，仅音源 URL 不同（`llmusic://` vs HTTP）
- **收缩态拖拽使用 `useDraggable` composable 实现**：`useDraggable.ts` 是一个纯鼠标事件轻量拖拽引擎，零外部依赖。拖拽期间 `transition: none` 防止卡顿，松手后恢复过渡动画。坐标被钳制在视口边界内（`bounds: true`），按钮/封面等交互元素排除在拖拽触发区域外

**关联模块**：
- playerStore（播放状态与统一引擎控制）
- lyricsStore（歌词加载）
- mediaStore（本地歌曲数据）
- uiStore（播放栏展开/收缩状态）
- `useDraggable` composable（收缩态拖拽引擎）
- `core/audio/engine.ts`（统一音频引擎）
- `lyricsHandlers.ts`（歌词获取 IPC 通道）
- `coverHandlers.ts`（封面获取 IPC 通道）

### 5.12 全局通知与错误反馈

**定位**：统一的用户操作反馈体系，取代原生 `alert()`（已全部移除）。

**核心功能**：
1. **Toast 队列**（`store/notification.ts`）：`notify/success/error/info/warning` 入口，右上角 `ToastContainer.vue`（App.vue 挂载）展示，默认 3s 自动消失，短时间（2.5s）内同文案去重
2. **错误分类提示**（`notifyError`）：将未知错误分为网络（axios 未达后端/超时）、业务（`ApiError` 携带错误码）、系统三类，给出对应文案
3. **登录状态联动**：`ApiError` 错误码为 2001/2002 时自动同步 auth store 登录状态
4. **页面级反馈**：各页面错误状态与空状态展示补齐（搜索失败、歌单为空、扫描失败文件列表等）；主进程侧的降级 warning（如下载元数据写入失败）透传到 Toast

## 6. 通用支撑能力

### 6.1 统一响应与异常处理（后端）

- 三层全局异常处理器（`ServiceException` / `RequestValidationError` / `Exception` 兜底），响应统一为 `{code, message, data}` 信封；API 层 13 个路由不再各自 try/except
- 错误码含 2001（未登录）/ 2002（凭证过期，SDK 凭证异常自动映射）/ 4002（RATE_LIMITED）
- `app/utils/logger.py → setup_logger` 提供统一格式的模块级日志，级别由配置驱动

### 6.3 状态管理（Vue + TypeScript）

- 类型化 Pinia Store；播放状态全量收编 player store，全局通知走 notification store

### 6.4 自定义组件库

- `components/custom/` 基础组件（按钮/输入/弹窗/进度/Toast 等），玻璃质感组件（GlassPanel/GlassButton）已移除

### 6.5 QQ Music API 客户端管理（后端）

- Client 单例经 `asyncio.Lock` 并发安全获取；登录/凭证刷新后重建单例，应用关闭时统一 `close` 释放
- 凭证加载 mtime 缓存 + 原子写盘 + 自动刷新（见 §5.4）

## 8. 典型业务闭环

### 8.1 发现并下载一首新歌（官方模块）

1. 用户在搜索页 [官方] Tab 输入关键词
2. 前端调用后端 `POST /api/v1/qqmusic/search` 接口
3. 后端通过 qqmusic-api 搜索 QQ 音乐曲库
4. 返回标准化搜索结果，前端 `DiscoverMusic.vue` 渲染歌曲列表
5. 用户点击下载 → 前端调用后端 `POST /api/v1/qqmusic/download-bundle` 获取元数据包（后端三段请求并行聚合）
6. 后端返回元数据包（歌曲 URL、封面 URL、歌词）
7. Electron 主进程流式下载音频文件，写入元数据（MP3 走 node-id3 / FLAC 走 ffmpeg Vorbis Comment），失败降级保留纯音频并 Toast 提示
8. 下载完成后自动导入本地音乐库
