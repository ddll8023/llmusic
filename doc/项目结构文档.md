# LLMusic 项目结构文档

> 更新日期：2026-07-26

## 1. 技术栈

| 类别 | 技术 | 说明 |
|------|------|------|
| 桌面框架 | Electron | 桌面窗口壳、系统托盘、文件系统访问、子进程管理、`llmusic://` 自定义音频流协议 |
| 前端框架 | Vue 3 | UI 渲染，Composition API + `<script setup lang="ts">` |
| 前端构建 | Vite 6 | 开发服务器与构建打包 |
| 类型系统 | TypeScript 5 | **全栈渐进迁移，strict 模式**。第一阶段前端 JS→TS（vue-tsc 检查），**第二阶段 Electron 主进程 JS→TS（tsc 编译到 dist-ts/）** |
| 前端状态管理 | Pinia | 全局状态管理，类型化 Store |
| 前端 UI | Font Awesome 4 | 图标库 |
| 前端虚拟滚动 | vue-virtual-scroller | RecycleScroller，BaseSongTable 全模式虚拟滚动 |
| 前端样式 | Tailwind CSS v4 | 原子化样式，`@tailwindcss/vite` 插件处理 |
| 前端 HTTP | axios | 调用后端 FastAPI 接口（官方搜索/下载），响应统一解包为 `ApiResponse<T>` |
| Electron 音频处理 | music-metadata | 读取本地音频元数据 |
| Electron 音频处理 | fluent-ffmpeg + ffmpeg-static + ffprobe-static | 音频转码（`llmusic://` 协议兜底）、封面提取、FLAC Vorbis Comment 标签写入 |
| Electron 音频处理 | node-id3 | MP3 音频标签写入（ID3v2.4，含 USLT 歌词/APIC 封面） |
| Electron 本地数据 | better-sqlite3 | SQLite 数据库（WAL 模式），管理歌曲/音乐库/歌单/设置，**原生模块需 electron-rebuild** |
| 后端框架 | FastAPI + Uvicorn | RESTful API 服务，三层全局异常处理器 |
| 后端序列化 | Pydantic + Pydantic Settings | 请求/响应校验与配置管理（env 前缀 `APP_`） |
| 在线音乐 SDK | qqmusic-api-python | QQ 音乐搜索、歌曲详情、歌单、下载链接、二维码登录、凭证刷新 |
| 后端 HTTP | httpx | 解析 QQ 音乐分享链接重定向（async + 超时） |
| Python 依赖管理 | uv + pyproject.toml | 虚拟环境与依赖管理，位于 `backend/.venv/` |
| 打包工具 | electron-builder + PyInstaller | 桌面应用打包与 Python 后端打包为 exe |

## 3. 启动边界

- 全栈开发启动：`start-dev.bat` 或 `npm run dev`
- 后端独立调试：`npm run dev:backend`
- 仅前端 + Electron：`npm run dev:electron`
- Electron 类型检查：`npm --prefix sys_electron run type-check`
- 前端类型检查：`npm --prefix sys_vue run type-check`
- 后端运行在 `http://127.0.0.1:9752`，前端 Vite 开发服务器在 `http://127.0.0.1:9753`

### 开发者须知（数据层迁移后首次运行）

- better-sqlite3 为原生模块，需针对 Electron 重新编译后才能启动：

  ```bash
  cd sys_electron && npm install && npx electron-rebuild -f -w better-sqlite3
  ```

- 旧版 lowdb 数据文件 `userData/db.json` 在首次连接数据库时会被**自动删除**（不做迁移），需重新扫描音乐库。数据库文件为 `userData/llmusic.db`（表：songs / libraries / playlists / playlist_songs / settings）。

## 4. 后端架构

后端采用 FastAPI 四层架构，**仅服务官方 QQ 音乐模块**。

```
API (app/api/) → Services (app/services/) → qqmusic_api (外部 SDK)
   ↓
Schemas (app/schemas/)  ← 数据校验与序列化
Core (app/core/)        ← 配置管理
Utils (app/utils/)      ← ServiceException / setup_logger
```

- 异常统一由 `main.py` 注册的三层全局处理器兜底（ServiceException / RequestValidationError / Exception），响应统一为 `{code, message, data}` 信封，API 路由层不写 try/except。
- 应用 lifespan：启动时触发凭证自动刷新（`ensure_credential_fresh`），关闭时释放 Client 单例。

## 5. IPC 通道一览

| 通道名 | 常量 | 模块 | 用途 |
|--------|------|------|------|
| `window-*` / `is-window-maximized` | `CHANNELS.WINDOW_*` 等 | `system/windowHandlers.ts` | 窗口控制 |
| `set-close-behavior` / `get-close-behavior` | `CHANNELS.SET_CLOSE_BEHAVIOR` 等 | `system/windowHandlers.ts` | 关闭行为设置（并入统一注册） |
| `scan-*` | `CHANNELS.SCAN_*` | `scan/scanHandlers.ts` | 音乐扫描 |
| `get-songs` / `get-song-by-id` / `delete-song` 等 | `CHANNELS.GET_SONGS` / 等 | `audio/songHandlers.ts` | 歌曲数据 |
| `get-song-cover` / `force-extract-cover` / `get-cover-from-file` | `CHANNELS.GET_SONG_COVER` / 等 | `audio/coverHandlers.ts` | 封面 |
| `get-lyrics` | `CHANNELS.GET_LYRICS` | `audio/lyricsHandlers.ts` | 歌词 |
| `get-song-tags` / `update-song-tags` / `*-tags-*-file` 等 | `CHANNELS.GET_SONG_TAGS` / 等 | `audio/tagHandlers.ts` | 标签编辑 |
| `get-playlists` / `create-playlist` / 等 | `CHANNELS.GET_PLAYLISTS` / 等 | `data/playlistHandlers.ts` | 播放列表 |
| `get-libraries` / `add-library` / 等 | `CHANNELS.GET_LIBRARIES` / 等 | `data/libraryHandlers.ts` | 音乐库 |
| `download-song-with-metadata` / `download-song-to-dir` | `CHANNELS.DOWNLOAD_SONG_WITH_METADATA` 等 | `download/downloadHandlers.ts` | 下载 |

> 本地音频播放**不走 IPC 通道**：渲染层统一音频引擎通过 `llmusic://audio/<songId>` 自定义协议直接流式读取（`system/audioProtocol.ts`，Range 分段响应，不支持格式经 ffmpeg 转码缓存到 `userData/transcode-cache`）。原 `player-*` 通道已随 playerHandlers 移除。
